第一期验收标准（来自开发手册，去掉 AI 两条）：
1. 前后端联通，PostgreSQL 正常读写，登录 / 退出正常。
2. 学生 A 看不到学生 B 的实验、数据、处理记录、周报；直接用编号请求接口和下载链接也被拒绝；外组管理员同样被拒绝；本组管理员和导师能看到。
3. 重新上传同名文件不会覆盖原文件；入库文件的 SHA256 与本地一致。
4. 一条处理记录能找到输入数据、脚本版本、参数和结果文件。
5. 周报"提交 → 需补充 → 修改 → 再提交 → 已阅"走通，每次修改有历史记录。
6. 核心流程有可运行的自动化测试。

## 第三期：采购与报销（完成，2026-11-17）

方案与已确认的规则见 [第三期采购与报销](../.agents/notes/implemented/feature/2026-11-17-phase3-procurement-and-reimbursement.md)。

- 经费来源（管理员维护，组内公开，停用不删）。
- 采购申请：明细、附件（PDF / JPG / PNG）；管理员初审 → 导师终审，管理员本人的申请直接终审，导师本人的申请初审通过即批准；退回必填意见，申请人可撤回。审批请求带上看到的状态和合计，变了就 409。批准后改了品名、数量或单价重新审批，审批记录保留。管理员标记已采购、已到货。
- 到货登记：新增设备、耗材入库时关联已到货的申请（设备和流水只显示单号）。
- 报销：登记、上传发票、待提交 → 已交财务 → 已到账，不审批；按经费 / 类别 / 人员 / 月份统计，导出 Excel。
- 通知：工作台"待我审批的采购""被退回的采购"；配置 SMTP 后各步骤发邮件；每周一由宿主机定时任务发财务提醒，也可手动发。
- 第二期遗留：工作台"待登记使用结果"只列最近 14 天内结束的预约。

验证范围（2026-11-17）：后端 270 个测试、前端 53 个测试、前端生产构建通过，后端生产镜像能构建并导入 `openpyxl`；设备并发模型检查在 `3ef63b4` 上重新确认。浏览器走通 verify-lab 的 `procurement.md` 和 `reimbursements.md`，包括审批人打开后申请人改价、审批被拒并刷新，以及手机宽度下的终审。
未验证：真实 SMTP 发信（含每周财务提醒）、宿主机定时任务、完整的生产 Compose 部署。邮件配置后来挪到了网页，见下面的"系统管理"。

## 发版、更新与备份（2026-11-18）

方案见[发版、更新与备份](../.agents/notes/implemented/process/2026-11-18-release-update-backup.md)。

- GitHub Actions：推送 `main` 和每个 PR 跑 `scripts/check.sh`；推送 `vX.Y.Z` 标签时先跑同样的检查，再从这条提交构建镜像推到 ghcr.io，并生成发布说明。
- 服务器：`.env` 的 `APP_VERSION` 选用镜像；`scripts/update.sh` 拉取 → 停站备份 → 切换 → 健康检查；失败时，迁移记录没变就自动退回，变了或无法核对就停站保留数据，由运维处理（见下文和 README）；`scripts/backup.sh`、`restore.sh` 用 restic，每天一份留 30 天、每月一份留 12 个月。
- "系统管理 → 版本"：当前版本、GitHub 上的最新版本和更新命令，有新版本时标签页写"有更新"。

验证范围（2026-11-18）：后端 370 个、前端 66 个测试和生产构建通过；"系统管理 → 版本"在浏览器里看过（从源码运行、仓库还没有正式发布时的显示，GitHub 实际返回 404）。在本机用一个本地镜像仓库代替 ghcr.io，造了三个测试版本，用真实的 Docker 和 restic 走过：
- 服务器上没有镜像时，`up -d` 自己拉取，健康检查通过；
- 备份后删组、删文件、加文件，`restore.sh latest` 把数据库和文件都恢复回来，多出的文件被删掉；
- `update.sh` 正常升级；
- 坏版本改动数据库结构后启动失败时，`update.sh` 保持停站并保留当前数据，运维核对更新窗口内的新写入后再决定恢复。

未验证：GitHub Actions 两个工作流还没在 GitHub 上跑过（要推送后才会跑）；ghcr.io 上镜像的公开设置；Linux 服务器上的实际运行（本机是 Windows 上的 Git Bash 加 Docker Desktop）；几百 GB 数据量下的备份时长。

    - 基础角色只有学生和导师，另有"管理员""终审人"两个可叠加的标签：
      - 导师看全组的实验记录、数据集和周报，并批阅、退回。
      - 管理员管设备、试件、耗材、经费来源、组会、注册审核和采购初审，任何人都可以是管理员。

      - 如果他是老师或不写周报的科研助理，运维在"系统管理 → 账号"把基础角色改成导师。
    - 原来的导师升级后是"导师 + 终审人"。
    - 同一张采购单：组里有别的终审人时，做过初审的人不能再终审。组里只有他一位时可以，审批记录写"初审和终审为同一人"。
