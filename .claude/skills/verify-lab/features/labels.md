# 设备和试件二维码标签

Status: 真实打印预览和手机/实物待验证；前端自动化验证了路由、权限、二维码输入与分页。

## Scenarios

- `labels-equipment-batch`：管理员在台账新建 3 件合成设备、勾选 3 行，点击「打印标签」。预览有 3 个编号、名称和二维码，显示当前站点。打开 A4 打印预览，确认 3 列、无页头菜单，实测 25 个标签的下一页从第 25 个开始。页面按钮只打开打印界面，不代表已经打印。
- `labels-specimen-single`：管理员从合成试件详情打开单件标签，核对编号、名称和二维码；不显示任何缺陷数据。
- `labels-scan-login`：复制二维码对应的详情地址模拟扫码。已登录的同组学生直接进入原详情；未登录学生登录后进入原详情；首次登录 `s_new` 改密后也进入原详情。
- `labels-role-and-group`：学生打不开打印页；外组管理员不能查询和生成这批标签，扫码也打不开原详情。
- `labels-phone-and-paper`：稳定域名就绪后，用 A4、实际大小、无页眉页脚小批试印。用手机实际扫设备和试件标签，核对详情地址、登录回跳、字号和识别距离。打印机输出与手机扫描是额外验收，不得以网页截图代替。

## Driving it with chrome-devtools MCP

在隔离验证栈中，按 [验证工具](../SKILL.md) 分角色使用独立浏览器上下文：管理员走台账和详情页；学生、首次登录学生及外组管理员分别走地址栏对应路径。打印样式可用浏览器打印媒体模拟和 PDF 验证；不要发往真实打印机。留存标签预览及首改密后链路的截图和快照，记录未跑的实物场景。
