# 站内通知

已登录的组内成员在左侧菜单 menuitem "通知"（有未读时后面是红色数字，例如 "通知 1"）打开列表、标记已读。站内通知不需要 SMTP。

## Sub-features

- `notifications-purchase`：采购提交和退回时，正确的收件人看到未读。
- `notifications-open`：点开通知后角标减少，并进入相应单据。
- `notifications-page`：仅未读筛选和全部标为已读。
- `notifications-isolation`：无关账号没有该通知。

## How to get to it (user POV)

登录，点左侧菜单 menuitem "通知 N"，在列表里点一条通知。

## Driving it with chrome-devtools MCP

1. 未走过：在隔离实例用学生甲提交一张采购申请（先按 procurement.md 准备经费来源）。切到管理员会话，正常刷新或切页后，菜单显示 "通知 1"。打开通知页应有“采购申请待初审”。
2. 未走过：点这条通知，确认进入刚才的采购详情、角标清零。管理员退回并填意见；学生甲刷新或切页后看见“采购申请退回修改”。
3. 未走过：点“查看全部”，打开“仅未读”，再点“全部标为已读”，确认列表和角标变为空。关掉“仅未读”能看到原通知。
4. 未走过：学生乙、外组管理员刷新后看不到学生甲或本组管理员收到的通知。保存截图、快照及隔离数据库的通知记录（含收件人、是否已读）。

## Gotchas

- 每个账号用独立浏览器上下文。隔离实例也用可控测试数据，不配置真实邮件。
- 未读数轮询只在可见标签页启用；主动刷新或切页可立即读取。
- 标记已读不会授予任何业务权限。已删除的目标记录或收件人组变更后，原链接可能不可访问。
