# 系统管理：邮件、课题组、账号、版本

运维账号（超级用户，不属于任何课题组）登录后直接进入"系统管理"，菜单里只有这一项；在这里配置全平台共用的发信邮箱、维护课题组和财务邮箱、开通和停用所有课题组的账号。授权码只能填、不能看。学生、管理员、导师看不到这个菜单，直接输入地址会回到工作台，接口 403。管理员可以在"报销与统计 → 统计"里改本组的财务邮箱。

## Sub-features

- `ops-landing`：`ops` 登录后地址是 `/system`，菜单只有 menuitem "系统管理"，右上角只显示"运维"（没有课题组名）。
- `mail-validate`：打开"启用邮件"但没填 SMTP 服务器，点 "保存"：字段下出现"启用邮件时必须填写 SMTP 服务器"。
- `mail-port-follows`：加密方式从 "SSL" 改为 "不加密"，端口从 465 变成 25；手动填过的端口不再跟着变。
- `mail-password-write-only`：保存后"授权码"输入框清空，占位变成"已设置，留空不修改"；保存请求的响应里没有授权码，只有 `password_set: true`。
- `mail-test-fail`：测试邮件失败时提示"发送失败：<服务器的原因>。<要检查什么>"（例如 535 后面是"账号或授权码不对……"），下面出现红框"最近一次发送失败（时间）"和同样的内容。
- `mail-test-ok`：改对授权码后再发，提示"测试邮件已发到 <地址>，请查收"，红框消失。
- `mail-history`：button "修改历史" 打开抽屉，按时间列出谁改了哪些字段；改授权码的那次只显示"原因：修改了授权码"，看不到授权码。
- `groups`：tab "课题组" 列出名称、财务邮箱、在籍成员数；新建同名课题组出现"已有同名的课题组"。
- `accounts-create`：tab "账号" 列出所有课题组的成员（没有运维账号）；新建导师账号后提示"已新建，对方首次登录时需修改密码"，状态有"未改初始密码"；该账号登录后被带到"修改密码"页。
- `accounts-deactivate`：对某账号点 "停用" → 确定，状态变"已停用"；该账号已经打开的页面刷新后回到登录页。
- `not-for-others`：`mgr` 打开 `/system` 回到工作台，菜单里没有"系统管理"，`/api/system/mail/` 和 `/api/system/accounts/` 都是 403。
- `finance-email`：`mgr` 在"报销与统计 → 统计"点 "财务邮箱"，填无效地址出现"请输入有效的邮箱地址"；填 `finance@example.edu` 保存后提示"财务邮箱已设为 finance@example.edu"。没设财务邮箱时点 "发送财务提醒" 提示"课题组还没有设置财务邮箱，请先点“财务邮箱”填写"。
- `version`：tab "版本" 显示当前版本、最新版本和检查时间。验证实例从源码运行，当前版本是"从源码构建（local）"，下面写"从源码构建的版本不提示更新"；仓库还没发布过正式版本时，最新版本一栏是"还没有发布过正式版本"，连不上 GitHub 时是"连不上 GitHub：<原因>"。有新版本时（只有自动化测试覆盖）标签名是"版本 · 有更新"，并显示命令 `bash scripts/update.sh <版本>`。

- `storage`：运维在「存储与备份」查看本地卷或 NAS 的身份检查结果。点「检查连接」只读，不挂载、不写 NAS，也不把身份匹配当成备份通过。

## How to get to it (user POV)

- `ops` 登录 → 左侧 menuitem "系统管理" → tab "邮件" / "课题组" / "账号" / "版本"。
- 邮件页：switch "启用邮件"、textbox "SMTP 服务器"、spinbutton "端口"、radio "SSL" / "STARTTLS" / "不加密"、textbox "账号"、"授权码"、"发件人地址"，button "保存"、"修改历史"；下面 textbox "收件地址" 和 button "发送测试邮件"。
- 课题组页：button "新建课题组"，每行 "编辑"；对话框 textbox "*名称"、"财务邮箱"。
- 账号页：textbox "搜索姓名、登录名、邮箱"，combobox "课题组"、"角色"，button "新建账号"；每行 "编辑"、"重置密码"、"停用" / "启用"。新建对话框：textbox "*学号 / 工号（登录名）"、"*姓名"，combobox "*课题组"、"*角色"，textbox "邮箱"、"电话"、"研究方向"、"*初始密码"。编辑时课题组只显示名称，不能改。

## Driving it with chrome-devtools MCP

前提：

- 刚启动的实例。
- 要验证真实的 SMTP 对话，在本机起一个只认授权码 `good-code` 的临时 SMTP 服务（例如 2525 端口，收到的邮件写进证据目录），用完停掉；不起也能走完除 `mail-test-ok` 以外的步骤（失败原因会是连接被拒）。
- 证据目录：`backend/var/verify-evidence/<日期>-system/`。

步骤：

- **落地页。** 以 `ops` 登录，`wait_for` "发送测试邮件"；确认地址是 `/system`，菜单只有"系统管理"。截图。
- **校验。** 打开"启用邮件"（见 Gotchas），点 "保存"，`wait_for` "启用邮件时必须填写 SMTP 服务器"。
- **保存设置。** 关掉"启用邮件"；点 radio "不加密"，端口变 25；"SMTP 服务器"填 `127.0.0.1`，"端口"填 `2525`，"账号"填 `lab@example.edu`，"授权码"填 `wrong-code`，点 "保存"，`wait_for` "已保存，立即生效"。用 `get_network_request` 把这次 PUT 的请求和响应存进证据目录：响应里没有授权码。
- **测试失败。** "收件地址"填 `ops@example.edu`，点 "发送测试邮件"，`wait_for` "最近一次发送失败"，提示和红框里都是"535 Error: authentication failed"。截图。
- **测试成功。** "授权码"填 `good-code`，打开"启用邮件"，点 "保存"；再点 "发送测试邮件"，`wait_for` "测试邮件已发到 ops@example.edu"，红框消失。看临时 SMTP 服务收到的邮件：发件人 `lab@example.edu`，收件人 `ops@example.edu`。
- **修改历史。** 点 "修改历史"，`wait_for` "修改了授权码"，抽屉里有"SMTP 服务器：（空） → 127.0.0.1""启用邮件：否 → 是"，没有授权码。截图并存快照，关闭抽屉。
- **课题组。** 点 tab "课题组"，点 "新建课题组"，名称填 `外组` → "保存"，`wait_for` "已有同名的课题组"；改成 `相控阵课题组`，财务邮箱填 `finance-pa@example.edu`，保存后列表多一行，在籍成员 0。
- **新建账号。** 点 tab "账号"，确认没有 `ops`。点 "新建账号"：`t_new` / `新导师`，课题组选"相控阵课题组"，角色选"导师"，初始密码 `Init-2026-pass!`，点 "保存"，`wait_for` "已新建，对方首次登录时需修改密码"。截图。新开 `isolatedContext: "t_new"` 用这个账号登录，页面跳到 `/password`，显示"首次登录，请先修改初始密码。"
- **停用。** 回到 `ops`，在"新导师"那一行点 "停用" → 确定，`wait_for` "已停用"。刷新 `t_new` 的页面，回到登录页。
- **存储状态。** 在隔离实例点「存储与备份」，默认应显示「服务器本地卷」；启用合成 NAS 后检查身份，替换测试标识后刷新，应显示「不可用」。同时核对普通成员请求 `/api/system/storage-status/` 得到 403。
- **其他人进不来。** 以 `mgr` 登录，打开 `/system`，回到 `/`；`evaluate_script` 读菜单文字和 `fetch('/api/system/mail/')`、`fetch('/api/system/accounts/')` 的状态码：菜单没有"系统管理"，两个都是 403。
- **财务邮箱。** `mgr` 打开"报销与统计"，点 tab "统计"，点 "发送财务提醒"，`wait_for` "请先点“财务邮箱”填写"。点 "财务邮箱"，填 `finance`，点 "保存"，`wait_for` "请输入有效的邮箱地址"；改填 `finance@example.edu` 保存，`wait_for` "财务邮箱已设为 finance@example.edu"。再点 "发送财务提醒"，提示"没有已交财务、尚未到账的报销，没有发送"。
- **第二视角。** 用 query.sh 读 `core.models.SiteSettings`（启用、服务器、端口、加密方式、`last_mail_error` 为空）、它的历史表字段里没有 `mail_password`、各课题组的财务邮箱，以及 `t_new` 的角色、课题组、`is_active=False`、`must_change_password=True`。

## Gotchas

- "启用邮件"开关真正的输入框是隐藏的，对快照里的 switch 用 `click` 会超时。用 `evaluate_script` 点页面上可见的开关：`document.querySelector('.el-switch').click()`，再看快照里 switch 是否变为 checked。
- 测试邮件用的是**已保存**的设置。表单改了没保存时点 "发送测试邮件"，只提示"测试邮件用的是已保存的设置，请先保存"，不会发。
- 页面第一次打开时会建一条设置记录，修改历史里因此有一条"运维 创建"；什么都没改就点 "保存" 也会留一条没有字段变化的"修改"。
- 下拉框的选项顺序就是课题组创建顺序：验证课题组、外组、新建的组。
- 学校真实 SMTP（SSL / STARTTLS 证书、授权码规则）没法在验证实例里验证。

## 存储用量（真实浏览器走查待执行）

运维打开「存储」标签，先查看已知大小和大小未知的文件数，再区分文件系统容量。用合成数据上传原始文件后核对字节与上传月份；新登记设备照片应计入设备栏；在另一个月替换照片后应只归入替换月份。旧照片大小未知时计入未知数量，只有上传时间未知时计入已知总量但不进趋势；成果全文计入未知数量。管理员或导师从成员页打开「本组存储用量」，核对成员、项目；学生无入口且 API 403。用隔离数据库读回原始字节数，不读取实际用户文件。

## 登录记录（待真实浏览器验收）

在隔离实例配置 `LOGIN_AUDIT_ENABLED=1` 并使用合成账号制造一次失败及一次成功，运维打开「登录记录」，核对结构化结果、时间、来源以及按账号筛选和分页；确认组管理员不能查。限流分钟与 180 天清理由隔离数据库测试；不要对真实服务制造大量请求或执行清理。
