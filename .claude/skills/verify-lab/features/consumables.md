# 耗材：库存与出入库流水

管理员在"耗材库存"里登记耗材品类、入库和盘点；组里每个人都能为自己登记领用和退回。库存不单独记，由全部流水相加得到；领用超过库存会被拒绝。库存低于安全库存时，列表里标"不足"，管理员工作台出现提醒。流水只增不改，记错了用盘点调整纠正。外组的人看不到。

## Sub-features

- `consumable-create`：管理员新建耗材后列表多一行，库存"0 根"并标"不足"。学生没有"新建耗材"和"更多"，只有"领用""退回""流水"。
- `stock-in`：管理员入库 10，库存变为"10 根"，"不足"消失。
- `take-out`：学生领用 12，数量框下出现"库存不足：当前 10 根"，库存不变；领用 6 并关联项目，出现"已登记领用"，库存变为"4 根"并标"不足"。
- `low-stock-workbench`：管理员工作台"需要你处理"里有一行：类型"库存不足"、"BNC 线 1 m"、"剩 4 根 / 安全库存 5"。
- `stocktake`：管理员点"更多 → 盘点"，填盘点实际数量 5，显示"差额 +1"，登记后库存"5 根"。差额为 0 时"登记"按钮不可点。
- `stale-stocktake`：两个页面打开同一盘点，A 提交后 B 登记应 409，旧表单关闭并刷新、提示重新核对，不自动重试。期间领用后退回到原库存也应拒绝；Django admin 的流水只读且无新增/删除入口。
- `history`：点"更多 → 流水"，抽屉里按时间倒序列出盘点调整 +1、领用 -6（学生甲、导波螺栓松动）、入库 +10。
- `return`：退回后库存增加，流水里是"退回 +N"和备注。
- `advisor-readonly`：导师和学生一样，只有 "领用"、"退回"、"流水"。
- `isolation`：外组管理员请求这个耗材和它的流水都是 404，列表为空。
- `purchase-link`（第三期）：入库对话框有 combobox "采购申请（已到货）"，流水里多一列"采购申请"。步骤见 [procurement.md](./procurement.md) 的"到货关联"。
- `labels`：管理员勾选几种耗材，点 "打印标签"，标签页每张是二维码、名称、规格 · 位置。二维码地址是 `/consumables?item=<id>&scan=1`。
- `scan-take`：打开这个地址（代替扫码），列表只剩这一种，直接弹出"领用：<名称>"，数量 1；提交后库存减 1，流水里经手人是自己。管理员的弹窗顶上有"领用 / 入库"可以切换。没登录时先登录再回到这里。
- `ledger`：tab "流水" 列出全组所有耗材的出入库（导师、管理员）或自己经手的（学生），最新在前；可按耗材、类型、经手人、项目、日期筛选，"导出 Excel"的行与页面一致。
- `order-more`：低于安全库存的一行"库存"后面有 button "发起采购"，打开新建采购申请，第一行品名、规格已填，数量为安全库存的两倍减去现有库存。

## How to get to it (user POV)

- 左侧展开 "设备耗材" → menuitem "耗材库存"。
- 工具栏：textbox "搜索名称、规格、位置"、checkbox "只看低于安全库存"、button "新建耗材"（仅管理员）。
- 每行最后一列：管理员是 button "领用"、"退回"、"更多"（下拉里是 menuitem "入库""盘点""批次管理""编辑""流水"）；学生和导师是 button "领用"、"退回"、"流水"。

## Driving it with chrome-devtools MCP

前提：

- 刚启动的实例，没有耗材，第一个耗材 id 为 1。
- 证据目录：`backend/var/verify-evidence/<日期>-consumables/`。

步骤：

- **新建耗材。** 用 `mgr` 登录，进入"耗材库存"，点 button "新建耗材"。textbox "*名称" 填 `BNC 线`，"规格" 填 `1 m`，"*单位" 填 `根`，spinbutton "安全库存" 填 `5`，"存放位置" 填 `A305 线缆柜`，点 button "保存"。列表出现一行，库存"0 根"，旁边"不足"。
- **入库。** 点这一行的 button "更多"，再点 menuitem "入库"，dialog "入库：BNC 线 1 m" 显示"账面库存 0 根"。spinbutton "*数量（根）" 填 `10`，"备注" 填 `采购到货`，点 button "登记"，`wait_for` "10 根"。
- **学生领用。** 用 `s_a` 登录，进入"耗材库存"，这一行只有 button "领用"、"退回"、"流水"。点 "领用"，数量填 `12`，点 "登记"，`wait_for` "库存不足"：数量框下是"库存不足：当前 10 根"。数量改为 `6`，combobox "项目" 选"导波螺栓松动"，"备注"填一句，点 "登记"，`wait_for` "已登记领用"，库存"4 根"、"不足"。截图。
- **管理员提醒。** `mgr` 打开工作台，`wait_for` "剩 4 根"，这一行行首是"库存不足"。截图。
- **盘点。** `mgr` 回到"耗材库存"，点 "更多" → "盘点"，dialog 显示"账面库存 4 根"、spinbutton "*盘点实际数量" 为 4、"差额 0"，button "登记" 不可点。点 button "增加数值" 一次，变为"差额 +1"；"备注"填一句，点 "登记"，`wait_for` "已登记盘点调整"，库存"5 根"，"不足"消失。
- **流水。** 点 "更多" → "流水"，抽屉"出入库流水：BNC 线 1 m"里依次是盘点调整 +1、领用 -6、入库 +10。截图。用 query.sh 读 `StockTxn`（加 `PYTHONIOENCODING=utf-8` 避免中文乱码），三条数量之和为 5。
- **退回（导师）。** 用 `adv` 登录进入"耗材库存"，这一行只有 "领用"、"退回"、"流水"。"领用" 2，再点 "退回"，数量 1，"备注"填一句，点 "登记"，`wait_for` "已登记退回"，库存加 1。点 "流水"，最新一行是"退回 +1 导师甲"和备注。
- **外组。** 用 `x_mgr` 登录，`evaluate_script` 请求 `/api/consumables/1/` 和 `/api/consumables/1/txns/`，都是 404；`/api/consumables/` 的 `count` 为 0。

## Gotchas

- 领用、退回、入库填正数；页面和流水里领用显示为负数。盘点填的是架上实际数量，页面自己算差额。
- "库存不足：当前 N 根"是数量框下的字段错误，同时右上角会闪一下"提交的数据有误"。
- 退回不检查"是不是自己领的"，流水里记着经手人。

### 批次管理（待浏览器验收）

用合成耗材入库 10 后从“更多”打开“批次管理”，填期初批号后确认总库存仍是 10。加一批已经过期的库存、一批即将到期的库存；学生点“领用”，确认默认选最早到期且有货的未过期批次。把一批领到零再退回，仍应能选中原批次。管理员工作台"批次到期"应显示 30 天内到期和已经过期、仍有库存的批次，过期的排在最前、标红、写"已过期"；耗材列表"最近到期"一列带圆点并写出"· 已过期"或"· N 天后到期"，不只靠颜色；入库和批次管理里的有效期用站内的日期选择框；耗材页"30 天内到期（含已过期）"筛出同样的耗材；外组不显示。用数据库读回验证期初转拨净额为 0。
