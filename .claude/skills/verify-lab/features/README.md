# 课题组管理平台浏览器验证清单

这里是在浏览器里验证用户可见行为的维护来源。驱动前先读本页，再按对应的功能文件操作。

## 基线前提

- 已运行 `bash .claude/skills/verify-lab/scripts/launch.sh`，并且 `doctor.sh` 全部为 ok。
- 应用地址 `http://127.0.0.1:5273`，数据库 `lab_verify`，种子账号和项目见 `../SKILL.md`。
- 每个功能文件都从刚启动的状态开始，除非文件里另写了前提。
- 只驱动本次 launch.sh 启动的实例。

## 驱动约定

- 每个账号一个 `isolatedContext`，名字就用账号名，例如 `s_a`。
- 按无障碍名称定位：按钮文字、输入框标签、菜单项文字。名称照抄下面文件里的写法，包括全角括号和斜杠两侧的空格。必填字段的名称前有星号，例如 combobox "*项目"、textbox "*名称"。
- 标着"未走过"的功能文件是按页面代码写的，第一次走时以快照为准，把不一致的地方改回文件里。
- 下拉框用"点击 → `ArrowDown` → `Enter`"选择，详见 `../SKILL.md`。

## 证据与跳过

- 证据放在 `backend/var/verify-evidence/<日期>-<功能文件名>/`。
- 界面证据：截图加无障碍快照。数据变化要再从第二个视角确认（query.sh 读数据库、看磁盘，或者换一个账号查看）。
- 走不通的步骤写清尝试了什么、缺什么前提；不要用另一条路径代替后报告"已验证"。

## 功能文件格式

每个文件以 H1 标题开头，接一段话说明用户看得到的行为，然后依次是四个 H2：`Sub-features`、`How to get to it (user POV)`、`Driving it with chrome-devtools MCP`、`Gotchas`。只写用户路径、元素名称、前提条件和可观察的结果，不写实现细节。

### Linux 合成数据试跑

浏览器试跑草稿新增独立 GitHub Actions 工作流，仅对 `test/browser-experiments-reports` 同仓分支 PR 启动。实验记录与周报分别用一个 Ubuntu 托管作业，复用现有合成账户；PostgreSQL、Django、Vite、ChromeDriver 都只监听回环地址。没有生产数据、凭据或调度。截图、可见文字和数据库只读断言存到 3 天过期的合成证据附件，不提交到仓库。

- 实验记录：第一份数据文件由合成夹具提供，第二份由浏览器上传；用数据库核对文件清单、版本固定、退回状态和历史。
- 周报：用数据库核对草稿、提交、补充、已阅、两条反馈，以及重复周没有新增记录。

上表只有在相应作业实际通过并检查证据后才标记日期与提交号。成员、登录、第四期遗留、手机宽度和试样走查仍未包含。
