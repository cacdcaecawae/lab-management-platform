# 采购：经费来源、采购申请、两级审批、到货登记

管理员维护经费来源。任何人都能填采购申请（经费来源、用途、明细），提交后先由管理员初审，再由终审人终审；管理员自己的申请直接到终审，终审人自己的申请由管理员初审、另一位终审人终审（组里没有别的终审人时初审通过即批准）。组里只有一位终审人、他又做了初审时，他可以终审，审批记录里写"初审和终审为同一人"；有别的终审人时他不能终审自己初审过的单。审批人可以通过或退回（退回必须写意见），申请人可以撤回。审批人点"通过"时，如果单据的状态或合计在他打开之后变了，会被拒绝并刷新。已批准后改了品名、数量或单价，单据回到待初审，之前的审批记录保留。管理员标记"已采购""已到货"后，新建设备和耗材入库时可以关联这张申请。采购申请是个人数据：只有申请人和本组管理员、终审人能看到（没有终审人标签的导师看不到别人的申请）。

## Sub-features

- `funds`：管理员新建经费来源，列表按"可用"在前、经费号排序；重复的经费号提示"本组已有相同经费号"。学生没有"经费来源"菜单，直接打开 `/funds` 回到工作台。
- `create`：学生新建申请，明细逐行填写，页面实时显示合计；明细的错误显示在那一行下面（例如"链接：请输入合法的URL。"），中间留着空行时也不错位。保存草稿后地址变为 `/purchases/<id>`，编号 `PR-2026-0001`。
- `total-limit`：明细合计超过 9,999,999,999.99 元（例如数量 10000、单价 1000000），点 "保存草稿" 后"明细"下面出现"合计不能超过 9,999,999,999.99 元，请检查数量和单价"，不保存；数量超过 1000000 时，那一行下面出现"数量：请确保该值小于或者等于 1000000。"。
- `attachments`：草稿上传 PDF / PNG 报价单，列表显示类型、文件名、大小、上传人；待初审、待终审时没有"删除"按钮。
- `attachments-after-review`：批准后申请人补传一张发票，只有这张新附件有"删除"按钮（确认后删除成功），审批人看过的报价单没有。
- `submit`：提交后变为只读视图，状态"待初审"，"进度：等待管理员初审"，只剩 button "撤回"。
- `isolation`：同组另一个学生、外组管理员打开这张申请是"记录不存在或无权查看"，附件下载地址 404，列表为空。
- `workbench`：管理员工作台"需要你处理"里有一行"待审批采购"；申请人被退回后，申请人工作台有一行"采购被退回"和"去修改"。
- `return`：不写意见点"退回修改"，意见框下出现"退回时请写明意见"，不发请求；写了意见后状态"草稿"、标签"被退回"，申请人页面顶部显示"管理员甲初审退回：<意见>"。
- `stale-review`：审批人打开页面后，申请人撤回、改价、重新提交；审批人再点"通过"，提示"单据已变化（状态或金额与你看到的不同），请刷新后再审"，页面自动刷新成新金额，审批记录不增加。
- `two-level`：管理员通过后"待终审"，管理员页面不再有审批按钮；终审人（`adv`）通过后"已批准"。
- `same-reviewer`：同一个人既是管理员又是唯一的终审人时，他做完初审还能终审，审批记录终审那一条后面写"初审和终审为同一人"。
- `mobile-review`：终审人在手机宽度（390×844）打开审批页：申请人、经费来源、提交时间、进度两两一行，下面是用途、明细、合计、附件；"审批记录"标题在第一屏，记录本身要往下滑；审批意见框和"退回修改""通过"固定在屏幕底部。
- `edit-after-approval`：申请人点"修改明细"，提示"修改品名、数量或单价后，申请会重新进入审批"；改单价保存后提示"明细已修改，申请重新进入审批"，状态"待初审"，合计更新，之前的审批记录都还在。修改历史的原因里写着改前改后的明细，时间显示为本地时间。
- `correction-still-valid`（未走过）：已批准的申请，申请人删光明细或把单价都改成 0 后保存：保存不了，"明细"下面提示"至少需要 1 条明细"或"合计必须大于 0"，状态仍是"已批准"。
- `draft-linked-by-reimbursement`（未走过）：学生的采购草稿被自己的一笔报销关联后，点"删除草稿"：提示"报销 RB-… 关联了这张草稿，先在报销里取消关联再删除"，草稿还在。
- `purchased-arrived`：管理员"标记已采购"→"标记已到货"，各有确认框。
- `arrival-links`：新建设备和耗材入库的表单里有 combobox "采购申请（已到货）"，只列已到货的申请。关联后，设备详情显示采购单号（管理员、终审人是链接，其他人只看到单号）；采购申请详情多出"到货登记"卡片，列出设备和入库记录。

## How to get to it (user POV)

- 左侧展开 "采购经费"：menuitem "采购申请"、"我的审批"（管理员、终审人）、"报销与统计"、"经费来源"（管理员）。
- 采购申请列表：textbox "搜索用途、品名、申请人"、combobox "状态"、checkbox "只看我的"（管理员、终审人）、button "新建采购申请"。点编号或整行进入详情。
- 详情页卡片右上角的按钮随身份和状态变化：草稿是 "删除草稿"（从未提交过时）、"保存草稿"、"提交审批"；审批中是 "撤回"（申请人）；已批准、已采购是 "修改明细"（申请人、管理员）和 "标记已采购" / "标记已到货"（管理员）。轮到的审批人在页面最后的卡片"审批"里填审批意见，点 "退回修改" 或 "通过"。

## Driving it with chrome-devtools MCP

前提：

- 刚启动的实例。样例文件目录里有 `quote.pdf` 和 `photo.png`。
- 证据目录：`backend/var/verify-evidence/<日期>-procurement/`。

步骤：

- **经费来源。** `mgr` 登录，打开"经费来源"，点 "新建经费来源"：textbox "*经费号" `NSFC-001`、"*名称" `国自然面上项目`、combobox "负责人" 选导师甲，"保存"。再新增一条，经费号仍填 `NSFC-001`，`wait_for` "本组已有相同经费号"；改成 `HX-002`、名称 `横向课题` 后保存。
- **新建草稿。** `s_a` 登录，菜单里没有"我的审批""经费来源"。进入"采购申请"，点 "新建采购申请"。combobox "*经费来源" 选一项，textbox "*用途" 填一句。第一行：textbox "品名" `5MHz 探头`，"规格型号" `Φ10`，spinbutton "数量" `2`，spinbutton "单价（元）" `1200`。点 "添加一行"：`耦合剂`，数量 `3`，单价 `45.5`，textbox "链接" 填 `淘宝店铺`。合计显示 "¥ 2,536.50"。点 "保存草稿"，`wait_for` "链接：请输入合法的URL。"。清空链接（点进去后 `Control+A`、`Backspace`，见 Gotchas），再 "保存草稿"，`wait_for` "PR-2026-"。
- **附件、提交。** 对 button "上传附件" 用 `upload_file` 传 `quote.pdf`，`wait_for` "quote.pdf"。点 "提交审批"，`wait_for` "等待管理员初审"。截图。
- **隔离。** `s_b`、`x_mgr` 各自打开 `/purchases/1`，看到"记录不存在或无权查看"；`evaluate_script` 读 `/api/attachments/1/file/` 为 404，`/api/purchases/` 的 `count` 为 0。
- **退回。** `mgr` 打开工作台，"需要你处理"里有一行"待审批采购"；在左侧展开 "采购经费"、点 menuitem "我的审批"，点 PR-2026-0001。`evaluate_script` 下载附件：200，`application/pdf`，`inline`。不写意见点 "退回修改"，`wait_for` "退回时请写明意见"；textbox "审批意见" 填 `请再补一家的报价单`，再点，`wait_for` "已退回申请人"。
- **重新提交。** `s_a` 工作台有一行"采购被退回"，点这一行的链接；顶部是退回意见。再传一份 `photo.png`，点 "提交审批"。
- **过期审批被拒。** `mgr` 刷新这张申请（合计 2,536.50），先不要点。`s_a` 点 "撤回" → 确认，把耦合剂单价改为 `48`，"提交审批"，`wait_for` "¥ 2,544.00"。回到 `mgr` 的旧页面点 "通过"，`wait_for` "单据已变化"；页面刷新为 2,544.00，审批记录仍只有那条退回。用 `get_network_request` 存下请求体（`total_seen` 是 `"2536.50"`）和 409 `stale` 响应。`mgr` 再点 "通过"，`wait_for` "等待终审人终审"。
- **手机终审。** `adv` 新开上下文，`emulate` viewport `390x844x3,mobile,touch`，登录后在工作台点"待审批采购"那一行的链接。截图第一屏。意见填 `同意，尽快下单`，点 "通过"，`wait_for` "已批准"。
- **批准后改价。** `s_a` 刷新，点 "修改明细"，探头单价改 `1250`，"保存修改"，`wait_for` "明细已修改，申请重新进入审批"，状态"待初审"，合计 2,644.00。点 "修改历史"，原因里有 "2×1200.00 … → … 2×1250.00"。然后 `mgr`、`adv` 依次再通过。
- **采购、到货。** `mgr` 刷新，点 "标记已采购" → 确定，再点 "标记已到货" → 确定，`wait_for` "已标记为已到货"。
- **到货关联。** `mgr` 在"设备台账"点 "新建设备"：编号 `PA-002`、名称 `5MHz 相控阵探头`，combobox "采购申请（已到货）" 选 PR-2026-0001，保存，详情里"采购申请"一行是链接 PR-2026-0001。`s_b` 打开同一台设备，`evaluate_script` 看 `/api/equipment/1/` 的 `purchase` 只有 `{id, code}`，页面上不是链接。`mgr` 在"耗材库存"新增 `耦合剂`（单位 `瓶`），点 "入库"：数量 `3`，combobox "采购申请（已到货）" 选这张，"登记"。`s_a` 刷新申请详情，`wait_for` "到货登记"：设备 PA-002 和"耗材入库 耦合剂 +3"。整页截图。
- **数据库。** query.sh 读 `PurchaseRequest`、`Approval`、`Attachment`、`Equipment.purchase_id`、`StockTxn.purchase_id`：审批记录 5 条，`total` 依次是审批人当时看到的金额；附件的存储名是 `procurement/<随机串>.pdf`。中文要正确保存，见 Gotchas。

- 在采购详情上传 PDF 附件并点文件名，确认弹窗可预览、下载，关闭后仍停留在原采购单。

## Gotchas

- 用 `fill` 把输入框填成空字符串，界面上清空了，但 Vue 没收到输入事件，提交的还是旧值。清空要点进输入框，按 `Control+A` 再按 `Backspace`。
- 经费来源下拉的顺序是可用在前、按经费号排序，`HX-002` 在 `NSFC-001` 前面；选完看下拉框旁边显示的文字确认。
- 审批意见框、审批按钮只给轮到的审批人：待初审只有管理员看得到，待终审只有终审人看得到，申请人自己永远看不到。
- 同一页面里附件的删除按钮叫"删除"，草稿的删除按钮叫"删除草稿"。
- query.sh 的标准输出在 Git Bash 里中文会乱码，存成证据文件也是坏的。要在 Django shell 里直接用 `open(..., "w", encoding="utf-8")` 写文件。

## 提交批次回归（2026-11-18 新增，待浏览器验证）

- 管理员打开待初审申请，学生撤回，仅更换品名（保持原合计）并重新提交；管理员旧页面点击“通过”或填写意见后“退回修改”，应提示“单据已变化”并刷新，没有新的审批记录。请求须包含旧 `submitted_seen`，响应为 409 `stale`。刷新后再次审批正常。
- 终审重复上述步骤（学生重提后管理员重新初审），终审人旧页面也应拒绝。
- 只上传附件、不重新提交时，当前批次审批仍可正常通过。
- API 缺失、null 或非法 `submitted_seen` 返回 400。前后端同步升级；旧客户端缺字段不能审批。
