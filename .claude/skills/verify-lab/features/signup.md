# 学生注册：注册链接、待审核、逐个或一键通过、拒绝

管理员在"成员"页打开"允许学生用链接注册"，把链接发给学生。学生打开链接填学号、姓名、邮箱、密码，提交后要等本组管理员审核，没通过之前登录不了。管理员在"成员"页顶部看到"待审核（N）"，勾选后"通过"或"拒绝"，也可以"全部通过"。待审核的人不出现在成员列表里，也选不到。

## Sub-features

- `signup-link`：`mgr` 打开开关后出现注册链接 `<网址>/register?code=<码>`、"复制链接""换一个链接"；关掉或换一个后，旧链接提交返回"注册链接已失效，请向课题组管理员要新的链接"。
- `signup-no-link`：直接打开 `/register`（没有码）只显示"注册要用课题组管理员发的注册链接打开，请向管理员索取。"，没有表单。
- `signup-apply`：用链接注册，提示"已提交，等待课题组管理员审核……"；两次密码不一致提示"两次输入的密码不一致"。
- `signup-waiting`：注册后马上登录，提示"账号正在等待管理员审核，通过后才能登录"；密码错时仍是"用户名或密码错误"。
- `signup-notify`：`mgr` 的通知铃铛多一条"<姓名> 申请加入课题组，请审核"，点开到"成员"页。
- `signup-hidden`：待审核的人不在成员列表里，学生 `s_a` 看成员页也看不到。
- `signup-approve`：勾选一个点"通过"，提示"已通过 1 人，现在可以登录了"，成员列表多一行"在籍"；该学生用自己设的密码登录直接进工作台，不要求改密码。
- `signup-approve-all`："全部通过"先弹确认框"通过全部 N 个申请？请先核对学号和姓名。"。
- `signup-reject`：勾选一个点"拒绝"，确认后该申请消失，同一学号可以重新申请。

## How to get to it (user POV)

- 管理员：左侧菜单"成员"，最上面一张卡片：开关"允许学生用链接注册"、注册链接、"复制链接""换一个链接"；有申请时下面是"待审核（N）"表格和"通过""拒绝""全部通过"。
- 学生：打开管理员发的链接，页面标题"学生注册"，填"学号（登录名）""姓名""邮箱""密码""确认密码"，点"提交申请"。
- 登录页下面写着"还没有账号？打开课题组管理员发的注册链接申请。"

## Driving it with chrome-devtools MCP

前提：

- 刚启动的实例。
- 证据目录：`backend/var/verify-evidence/<日期>-signup/`。

步骤：

- **没有链接。** 新开 `isolatedContext: "applicant"`，打开 `http://127.0.0.1:5273/register`，`wait_for` "注册要用课题组管理员发的注册链接打开"，快照里没有 textbox。
- **打开注册。** 以 `mgr` 登录，点 menuitem "成员"。点 switch "允许学生用链接注册"（见 Gotchas），`wait_for` "已生成新的注册链接"；用 `evaluate_script` 读 textbox "注册链接" 的值，形如 `http://127.0.0.1:5273/register?code=...`。截图。
- **申请。** 在 `applicant` 页面打开这个链接，"学号（登录名）"填 `s_c`，"姓名"填 `学生丙`，"密码"填 `Apply-2026-pass!`，"确认密码"填 `other`，点 "提交申请"，`wait_for` "两次输入的密码不一致"。把"确认密码"改对再提交，`wait_for` "已提交，等待课题组管理员审核"。再用同一链接申请 `s_d` / `学生丁`。
- **等待审核。** 在 `applicant` 页面打开 `/login`，用 `s_c` / `Apply-2026-pass!` 登录，`wait_for` "账号正在等待管理员审核"；把密码改成 `wrong-pass!` 再登录，提示"用户名或密码错误"。
- **通知与列表。** 回到 `mgr`，刷新"成员"页：卡片里有"待审核（2）"，下面的成员表格里没有"学生丙""学生丁"。通知铃铛的未读数是 2。以 `s_a` 登录看"成员"页，也没有这两人。
- **通过一个。** `mgr` 勾选"学生丙"那一行，点 "通过"，`wait_for` "已通过 1 人"；成员表格多一行"学生丙""在籍"，卡片变成"待审核（1）"。`applicant` 页面用 `s_c` / `Apply-2026-pass!` 登录，直接进工作台，`wait_for` "你好，学生丙"。
- **拒绝。** `mgr` 勾选"学生丁"，点 "拒绝"，确认框里点 "确定"，`wait_for` "已拒绝 1 人"，"待审核"一节消失。
- **换链接。** `mgr` 点 "换一个链接" → 确定。`applicant` 页面用旧链接申请 `s_e`，`wait_for` "注册链接已失效"。
- **第二视角。** `query.sh 'from accounts.models import User; print(list(User.objects.filter(username__in=["s_c","s_d","s_e"]).values_list("username","is_active","pending","must_change_password","group__name")))'`，输出只有 `('s_c', True, False, False, '验证课题组')`。

## Gotchas

- 开关的真正输入框是隐藏的，对快照里的 switch 用 `click` 可能超时，用 `evaluate_script` 点页面上可见的开关：`document.querySelector('.el-switch').click()`。
- 待审核表格的勾选框也一样：按姓名找到行，再点行里的 `.el-checkbox`（第一张 `.el-card` 是注册卡片）。
- 通知铃铛的弹出层刚打开时显示"暂无通知"，加载完才出现内容，要 `wait_for` 通知文字；Esc 关不掉，再点一次铃铛。
- 无头 Chrome 里"复制链接"的结果读不回来，链接以输入框的值为准。正式部署用 HTTP 内网地址时浏览器不提供剪贴板接口，页面改用选中文字再复制，这条路径只有代码，没有自动化测试。
- 注册按来源地址每小时限 10 次，同一实例里别反复申请。
- 同一个浏览器上下文登录后就有会话，申请人要用单独的 `isolatedContext`。
