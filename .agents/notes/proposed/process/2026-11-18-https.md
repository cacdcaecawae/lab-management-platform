# Agent Note: 正式域名的 HTTPS

Status: proposed

## Problem

`infra/nginx.conf` 只有 HTTP。没有 HTTPS 时，必须设 `DJANGO_SECURE_COOKIES=0` 才能登录，而且只能在校园网或 VPN 内使用。正式上线要用域名加 HTTPS：开发手册第 9 节要求国内服务器的域名先做 ICP 备案，导师在国外也要能访问。

**前提**：用户提供域名，ICP 备案完成，DNS 已解析到服务器。在那之前只能准备配置，不能实际签发证书。

## Proposal

- **证书**：Let's Encrypt，用宿主机上的 certbot 以 webroot 方式签发和续期：
  - Nginx 在 80 端口提供 `/.well-known/acme-challenge/`，目录挂载宿主机的 `/srv/lab-certbot/www`；
  - 证书挂载宿主机的 `/etc/letsencrypt`，只读；
  - 续期用 certbot 自带的定时器，`--deploy-hook` 里执行 `docker compose ... exec web nginx -s reload`。
- **Nginx**：新增 `infra/nginx.https.conf`，由 `.env` 的 `NGINX_CONF`（默认 `nginx.conf`）选择，挂载进 web 容器。不要改镜像里的默认配置：本机试用和内网部署仍然只用 HTTP。
  - 80 端口：保留 ACME 路径；新增 `location = /healthz`，只允许 127.0.0.1，转发到后端的 `/api/auth/csrf/`；其余全部 301 跳到 https。
  - 443 端口：现有 `location` 原样搬过去，加 `ssl_certificate`、TLS 1.2 及以上，以及 `Strict-Transport-Security: max-age=31536000`（先用短时间试运行一周，确认无误后再改长）。
  - `/admin/` 和登录接口的限速配置不变。
- **健康检查**：`scripts/update.sh` 现在请求 web 容器里 80 端口的 `/api/auth/csrf/`。开了 HTTPS 以后，这个请求会被 301 跳转，所以健康检查改为请求 `/healthz`，HTTP 和 HTTPS 两种配置都有这个地址。
- **Django**：`DJANGO_SECURE_COOKIES=1`（默认），`DJANGO_CSRF_TRUSTED_ORIGINS=https://<域名>`；前面只有 Nginx 一层代理，所以 `NUM_PROXIES` 保持 1；如果学校另有 HTTPS 网关，按 README 改成 2。
- **compose**：web 服务映射 443；新增 `HTTPS_PORT` 变量，默认 443。
- **文档**：README"服务器部署"一节新增从签发证书到打开 HTTPS 的步骤；`infra/server.env.example` 新增 `NGINX_CONF`、`HTTPS_PORT`。

## Alternatives considered

- **用 Caddy 替代 Nginx，自动管理证书**：最省事。但要重写全部 Nginx 配置（2 GB 上传、限速、静态文件），已经验证过的行为要重新验证一遍。
- **certbot 跑在容器里**：宿主机不用装 certbot。但要多一个容器，还要共享卷和定时任务；宿主机装 certbot 是最常见、文档最多的方式。
- **学校统一的 HTTPS 网关**：不用管证书。但要看学校网络中心是否提供，而且代理层数会变（`NUM_PROXIES=2`）。如果学校提供，这篇笔记大部分就不需要了，到时改为 rejected。

## Acceptance criteria

- 没有域名时能验证的部分：
  - 用自签名证书和 `NGINX_CONF=nginx.https.conf` 在本机起测试栈：HTTP 请求被 301 跳转，HTTPS 能登录，Cookie 带 `Secure` 标志；
  - `/healthz` 在容器内返回 204，从宿主机访问返回 403；
  - `update.sh` 在 HTTP 和 HTTPS 两种配置下健康检查都通过。
- 有域名以后：签发真实证书；用 SSL Labs 检查，评级 A 或以上；续期用 `certbot renew --dry-run` 验证。
- 默认配置（`nginx.conf`）的行为不变：本机试用栈仍然只走 HTTP，`trial.ps1 up` 正常。

## Risks

- HSTS 一旦以长时间生效，域名就再也不能退回 HTTP，所以先用短时间试运行。
- 证书续期失败会导致全站无法访问。续期日志要有人看；[每日提醒邮件](../../implemented/feature/2026-11-18-scheduled-reminder-mail.md)上线后，可以加一条"证书 14 天内到期"提醒运维。
