# Agent Note: 耗材批次与有效期

Status: proposed

## Problem

开发手册把"耗材批次与有效期"列为暂不做。超声检测用的耦合剂、清洗剂、部分胶粘剂有保质期：过期的耦合剂会影响声耦合，数据不可靠。现在耗材只有总库存（由流水汇总），不知道库里哪一批什么时候过期，也没法做到先用快过期的。

需要用户确认的点：哪些耗材要按批次管。默认做成每个耗材单独开关，不开的保持现状。

## Proposal

**模型**（`inventory` app）：

```
Consumable.tracks_batches  Bool，默认 False
Batch(consumable → Consumable PROTECT, batch_no ≤50, expires_on Date null, created_at)
    唯一约束：(consumable, batch_no)
StockTxn.batch → Batch null PROTECT
```

**规则**（只对 `tracks_batches=True` 的耗材生效）：

- **入库**：必须填批号，有效期可填；批号不存在就新建批次，存在就加到那一批上。
- **领用、退回、盘点调整**：必须选批次；每个批次的库存（该批流水之和）不能小于 0，超出就 400，提示"该批次库存不足：当前 N"。
- **耗材总库存**：仍然是全部流水之和，现有的盘点版本校验（`stock_version_seen`）不变。
- **打开开关**：只有当前库存为 0 时才能打开，否则 409，提示先盘点清零，或者在同一个请求里带上"期初批次"（批号、有效期），把当前库存作为一笔入库记到期初批次。
- **关闭开关**：只有每个批次的库存都为 0 时才能关闭。
- **建议领用的批次**：接口返回各批次的库存，按有效期升序（无有效期的排最后）；前端默认选第一个有库存的，可以改。

**接口**：

- `Consumable` 新增 `tracks_batches`，以及 `batches: [{id, batch_no, expires_on, stock}]`（只含库存大于 0 的）、`nearest_expiry`。
- `StockTxn` 新增 `batch_no`（入库）或 `batch_id`（其他类型）。
- 列表新增筛选 `expiring_within=<天数>`。

**前端**：

- 耗材表格新增"最近到期"一列，30 天内到期标橙、已过期标红。
- 入库对话框在开关打开时多出"批号""有效期"；领用、退回、盘点对话框多出"批次"下拉框，显示各批次的库存和有效期。
- 管理员工作台新增"30 天内过期的批次"。

## Alternatives considered

- **每次领用自动扣最早到期的批次（先到期先出）**：省一步操作。但实际拿的未必是最早那一批，账就和实物对不上了；所以默认选中最早的，让人确认。
- **所有耗材都按批次管**：规则统一。但线缆、探头楔块这类东西没有有效期，强制填批号只会制造麻烦。
- **只给耗材加一个"有效期"字段**：最简单。但同一种耗材常常有几批不同的有效期，一个字段表达不了。

## Acceptance criteria

- 后端测试：
  - 开关开着时，入库没批号、领用没批次都返回 400；
  - 批次库存不能为负；
  - 开关的两个条件；
  - 期初批次；
  - 盘点版本校验仍然有效（复用 `test_stocktake_version.py` 的场景加上批次）；
  - 没开开关的耗材，行为和现在完全一样（现有测试原样通过）；
  - 外组隔离。
- 前端测试：领用对话框默认选中最早到期且有库存的批次。
- 浏览器：管理员打开开关、入两批不同有效期的耦合剂；学生领用时默认选中早到期的那一批；管理员工作台出现即将过期的批次。更新 `features/consumables.md`。

## Risks

- 加锁：现有的入库和领用锁住耗材这一行再计算库存。批次库存的计算要在同一把锁下进行，不能另开查询，否则两个人同时领同一批会超领。
- 迁移：`StockTxn.batch` 可为空，不需要回填历史数据。
