# Agent Note: 设备与试件二维码标签

Status: proposed

## Problem

开发手册把"设备二维码"列为暂不做。实验室里，设备和试块上只贴着编号。要预约设备、查手册、登记借用，得先回到电脑前，在列表里按编号查。贴一张二维码，手机一扫就能打开设备详情（上面有"预约"按钮和知识库资料）或试件详情（有"借用""登记归还"）。

## Proposal

- **只做前端，不加后端接口**：二维码内容就是页面地址，例如 `${location.origin}/equipment/12`、`${location.origin}/specimens/3`。扫码后，没登录的会先到登录页，登录后回到原页面（要确认路由守卫在登录后会回到原地址，不会时补上 `redirect` 参数）。
- **新增打印页** `/labels?type=equipment|specimen&ids=1,2,3`，放在公共的 `views/LabelsView.vue`，只给管理员：
  - A4 纸每页 3 列 × 8 行，每张标签有二维码、编号、名称；
  - 打印用 `@media print`，隐藏菜单和页头；
  - 页面顶部提示"二维码里是当前浏览器地址栏的域名，请在正式域名下打印"。
- **入口**：设备台账、试样与标准件的列表加多选框，管理员勾选后点"打印标签"；详情页加"打印标签"，只打这一件。
- **依赖**：新增 npm 包 `qrcode`（MIT，常用，没有原生依赖），用它的 `toDataURL` 生成图片。

## Alternatives considered

- **后端生成二维码图片**（Python 的 `segno`）：前端不加依赖。但要新增接口，还要处理权限和缓存，打印页还是要前端来排版。
- **只印编号，不印二维码**：零开发。但手机上还是要手动搜索，省不了几步。
- **二维码里放一个与地址无关的短码，再由一个中转地址跳转**：将来换域名，标签不用重印。但多一层跳转和一张表。目前域名还没定，所以在正式域名定下来之前不要大量打印；定下来以后，直接用页面地址最简单。

## Acceptance criteria

- 前端测试：打印页对每个 id 生成一个二维码，内容等于 `origin + 详情路径`（用 mock 的 `qrcode` 校验调用参数）；非管理员访问被路由守卫挡回工作台（`meta.manager`）。
- 已登录和未登录两种情况下扫码打开都正确：没登录时先进登录页，登录后回到详情页。在浏览器里直接打开 `/equipment/1` 模拟扫码。
- 浏览器：勾选 3 台设备打印，打印预览（`emulate` 打印媒体，或者截图）里标签排版正确。新增功能文件 `features/labels.md`。
- `frontend/package-lock.json` 在 Linux 容器里重新生成（Windows 上的 npm 会丢掉 `@emnapi` 依赖，见项目记忆），CI 通过。

## Risks

- 标签的耐久性（试块会接触耦合剂和油）是打印材料的问题，不归软件管。可以在页面上建议使用覆膜标签纸。
