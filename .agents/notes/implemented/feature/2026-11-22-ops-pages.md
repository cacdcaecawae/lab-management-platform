# Agent Note: 运维界面拆成侧栏六页，存储与备份、存储用量合成一页

Status: implemented

## Problem

- 用户（2026-11-22）："哪个ops运维的界面在优化一下把"。走查运维账号的"系统管理"（1440 宽和 390 宽，截图在 `backend/var/verify-evidence/2026-11-22-ops-ui/before-*.png`）：
  - 侧栏只有"系统管理"一项，邮件、课题组、账号、存储与备份、存储用量、版本、登录记录七个标签挤在一张卡片里。手机上标签条要左右滑，"存储与备份 · 需处理"被截断。
  - "存储用量"把课题组 × 模块、课题组 × 月份铺成两张长表：两个课题组就是 12 + 24 行，几乎都是 0 B，下面才是一句"不满三个完整月份，暂不估算"。
  - "存储与备份"写"剩余空间 47.4 GB"，"存储用量"写"剩余 118.5 GB"。前者是上传暂存目录和附件目录里小的那个（`core.disk.free_bytes`，上传按它拒绝），后者是附件所在磁盘；这台开发机上暂存在 C 盘、附件在 F 盘，所以对不上。启用 NAS 的站点也一样（暂存在服务器 `/tmp`）。
  - 账号表的状态一栏，"在籍"下面再叠一个"未改初始密码"，那一行变高。
  - 备份几行的标签（"最近成功的备份""最近一次恢复演练"）超过 120px 的标签列，折成两行。
- 问了用户两种改法，用户选了"拆成侧栏多页"。

## Decision

- **路由**：`/system/storage`、`/system/accounts`、`/system/groups`、`/system/mail`、`/system/version`、`/system/logins`，都要求超级用户；`/system` 跳到存储与备份，路由守卫照旧把运维送到 `system`，所以运维登录后先看到存储与备份。六页由同一个 `SystemView.vue` 按路由名画对应的组件，各组件不变。
- **侧栏**（`layouts/nav.ts`）：系统管理这个模块有六页，每页带自己的图标。只看得到这一个模块的人（没有课题组的运维）直接把六页列成六项，不套"系统管理"一层；有课题组的超级用户看到的是一组可收起的"系统管理"，和别的模块一样。系统管理的页面不进顶栏标签条。
- **菜单标记**：原来写在标签名里的"存储与备份 · 需处理""版本 · 有更新"，改成菜单项后面的胶囊：需处理红色（和"通知"未读数同一个样式），有更新蓝色。状态放在新的 `stores/ops.ts`，侧栏在超级用户登录后加载一次；存储与备份、版本两页"重新检查"的结果写回这里，标记跟着变。加载失败的，打开下一个系统管理页时再取；版本页没取到时只显示"当前版本 —"和"重新检查"。这两个接口放在公共的 `api/opsStatus.ts`：公共代码不能引用模块（`scripts/check_module_deps.py`），`systemApi` 照旧包含它们。
- **存储与备份一页**（`SystemStorage.vue`）：
  - 主存储：附件保存位置；NAS 连接检查只在启用 NAS 时出现；"磁盘"一行是附件所在磁盘的用量条和"已用 …，共 …，剩余 …"。上传暂存目录比附件磁盘少 1 GB 以上时多一行"上传暂存目录 剩余 …"，"不足，已暂停上传"标在真正卡住上传的那一行。
  - 备份：三行标签缩成"最近成功""最近失败""恢复演练"，标签列 140px。
  - 各课题组的文件：一个课题组一行，列是六个模块和合计，有大小未知的文件写"，另 N 个大小未知"。
  - 近 12 个月上传、现在还在的文件：同样一个课题组一行，只列有上传的月份；一个都没有时写"近 12 个月没有上传过文件"，也就不再说"暂不估算"。
  - `StorageUsage.vue` 只剩管理员、导师在"成员"页看的本组用量。
- **账号表**：状态只放一个标签：待审核、未改初始密码、在籍、已停用。
- 接口、后端不变。

## Alternatives considered

- **保留一页七个标签，只修各标签的内容，手机上把标签条换成下拉框**：改动小，但运维的全部工作都在这一页，侧栏却空着；七个标签再加一个也会更挤。用户选了拆页。
- **用量画成柱状图**：课题组少、数字大多是 0 时，一张小表更直接，也不用新加图表组件。
- **"剩余空间"只显示一个数（小的那个）**：上传确实按小的那个拒绝，但运维要知道是哪块盘满了才能处理，所以附件磁盘总在、暂存只在它更小时出现。

## Consequences

- 原来的 `/system` 地址还能用（跳到存储与备份）。文档里"系统管理 → 邮件"这类说法仍然对得上：有课题组的超级用户侧栏里就是这样一组；运维看到的是同样几页。
- 运维第一次打开时会多两个请求（侧栏加载状态、页面自己检查），量很小。
- 验证：
  - 前端测试：`SystemStorage.test.ts` 改成真实的 Element Plus 组件，覆盖用量条、暂存目录何时出现、"不足"标在哪一行、课题组 × 模块表、只列有上传的月份；`nav.test.ts` 覆盖运维的六项侧栏、`/system` 跳到存储与备份、有课题组的超级用户看到"系统管理"一组、系统管理的页面不进标签条；`router.test.ts` 改成落到 `system-storage`。
  - verify-lab 浏览器（`ops`，1440 和 390 宽，截图 `after-*.png`）：侧栏六项和"需处理"；记一次成功的备份后"需处理"消失，再记一次失败、点"重新检查"又出现；账号表一行一个状态标签；手机上抽屉里六项，用量表变成卡片；`mgr` 打开 `/system/accounts` 回到工作台，`/api/system/storage/` 403。
  - 验证实例里各组都没有文件，用量表在浏览器里只看到 0 B，有数据的样子靠前端测试。
  - 发布前复审查出两处，已修：`stores/ops.ts` 直接引用了 `modules/system/api`，违反模块依赖规则（后端测试 `test_module_deps` 失败；当时只跑了前端测试）；版本请求失败一次后，版本页一片空白，切走再回来也不再请求，只能刷新整个网页（v0.1.5 的版本标签也会空白，但离开系统管理再回来会重新请求；改成共用状态后连这样也不行了）。`stores/ops.test.ts` 和 `SystemVersion.test.ts` 覆盖；浏览器里让第一次版本请求失败：直接打开版本页时显示"当前版本 —"和"重新检查"，点了就取到；从存储与备份切过来时自动再取，请求数 2（截图在 `backend/var/verify-evidence/2026-11-23-review/`）。
