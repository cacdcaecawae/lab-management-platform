# Agent Note: 第四期：知识库、组会、成果归档（在平台里自建，不接外部系统）

Status: implemented

## Problem

开发手册第四期要做三块：

- **知识库**：分类为设备 SDK、使用手册、调试经验、操作规范、代码模板。每篇有标题、分类、关联设备、标签、说明、作者和文件；上传新版本时保留旧版本；能按标题、标签和说明搜索。
- **组会**：日期、议程（汇报人和内容）、附件、纪要；行动项要有负责人、截止日期和状态。
- **成果归档**：论文、专利、获奖、软著；记录标题、作者、期刊或会议（专利填授权号）、日期、状态、全文；按年份和类型导出 Excel。

验收标准：按设备名能找到该设备的 SDK 和手册；能导出指定年份全部已录用论文的清单，并附带全文。[第二期笔记](../../implemented/feature/2026-11-17-phase2-equipment-and-consumables.md)已经把设备的手册和 SDK 留给了知识库。

用户要求动手前先调研，看能不能复用现成的开源项目。手册第 3 节已经比较过整套替代方案（eLabFTW、飞书多维表格），结论是没有一个能同时覆盖可复现的数据、两级采购和周报。这次只看第四期这三块单独能不能接现成的东西。

约束：

- 按[角色与课题组隔离](../../implemented/architecture/2026-11-16-roles-and-group-isolation.md)，三块都是**公共数据**：本组全员可看，外组 404。
- 尽量不加依赖（见[最少依赖](../../implemented/process/2026-11-16-minimal-dependencies.md)），不加要单独运维的服务。

2026-11-17 用户确认方案，5 个待确认问题全部按推荐做法。

## Decision

**三块都在平台里自建**，理由见"调研结果"。复用平台已有的东西，不新增依赖：

- 文件上传与下载：权限检查后才能下载，存储名由服务器生成；PDF 和图片 inline，其他类型作为下载返回，防止上传的 HTML 在本站打开。
- 修改历史：`django-simple-history`。
- 课题组隔离：越权一律 404。
- 导出：Excel 用已有的 `openpyxl`，打包全文用标准库 `zipfile`。
- 搜索：子串匹配（`icontains`，即 `ILIKE`）。PostgreSQL 自带的全文检索不会切分中文，要加 zhparser 一类的扩展，这个规模不值得。
- 工作台卡片。

### 知识库（app `knowledge`）

- **数据**
  - `Doc`：课题组、标题、分类、关联设备（可空，只能选本组设备）、标签（最多 10 个）、说明（纯文本）、作者，有修改历史。
  - `DocVersion`：版本号（1、2、3……，在文档行锁下递增）、文件、文件名、大小、SHA256、本版说明、上传人、上传时间。旧版本全部保留，列表显示最新版。文档可以没有文件。上传新版本不算文档字段的修改，不写修改历史。
- **权限**：全员可以新建；作者和管理员可以编辑、上传新版本；只有管理员能删除（待确认 1）。
- **文件**：任意类型，单个上限沿用平台的 2 GB（待确认 2）。
- **搜索**：关键字同时匹配标题、标签、说明、关联设备的编号和名称；可以按分类、设备、标签筛选。
- **入口**：菜单"知识成果 → 知识库"；设备详情页的"资料"一栏列出关联这台设备的文档，点标题打开知识库并选好设备筛选。

### 组会（app `meetings`）

- **数据**：`Meeting`（日期、标题默认"组会"、纯文本纪要，有修改历史）、`AgendaItem`（汇报人、内容、顺序）、`ActionItem`（负责人、事项、截止日期可空、完成时间）、`MeetingFile`（附件）。
- **权限**（待确认 3）：全员可看；管理员建组会、编辑议程、纪要和行动项；议程里的汇报人和管理员可以上传附件，上传人和管理员可以删；负责人和管理员可以把行动项标为完成或取消完成。
- **编辑行动项**：按 `id` 更新已有项、新增没有 `id` 的项、删除没列出的项，已有项的完成状态保留。
- **附件**：任意类型，单个上限 2 GB。
- **入口**：菜单"项目 → 组会"；工作台"我的行动项"列出本人未完成的事项，截止日期近的在前，过期的标红，全部完成后卡片消失。不发邮件（待确认 5）。

### 成果归档（app `achievements`）

- **数据**：`Achievement`：类型、标题、作者（按署名照抄，含外单位）、本组成员（多选，用于按人筛选）、出处 / 编号、日期、状态、DOI 或链接、全文（可选）、备注，有修改历史。
- **状态**：论文为投稿中 / 已录用 / 已发表；专利为申请中 / 已授权；获奖为已获奖；软著为已登记。类型和状态不匹配 400。
- **权限**：全员可以登记、可以导出；登记人、署名的本组成员、管理员可以修改和上传全文；只有管理员能删除。
- **全文**：只收 PDF，单个不超过 50 MB；替换后旧文件在事务提交后删除。
- **导出**：按类型、年份、状态、成员、关键字筛选后导出 `.xlsx`；"导出（附全文）"导出 `.zip`，里面是清单加全部全文，全文按清单序号命名，清单的"全文"列写对应路径。状态筛选里的"已录用（含已发表）"对应 `status=accepted,published`（待确认 4）。

### 调研结果（复用的候选）

| 模块 | 候选 | 能做什么 | 为什么不直接用 |
|---|---|---|---|
| 知识库 | BookStack（MIT，PHP + MySQL） | 书 / 章 / 页结构，页面修订历史，页面附件，支持 LDAP / SAML / OIDC 登录 | 以写页面为主；附件可以替换文件，但官方文档没说保留旧版本，满足不了"新版本保留旧版本"。没法关联平台的设备台账，设备详情页也列不出它的资料。要多运维一个服务和一个 MySQL，还要另配登录 |
| 知识库 | Wiki.js、Docmost（AGPL，Node） | 现代化的 wiki 编辑器，有页面历史 | 同上：页面为主、不关联设备、要另外部署和登录。AGPL 对内部使用没有影响 |
| 知识库 | django-wiki（Django 应用，0.12 支持 Django 5.2） | 能装进同一个 Django，共用账号 | 自带服务端渲染的 Bootstrap 页面，和平台的 Vue 界面是两套；以 wiki 页面为中心，不按"文件 + 版本"组织 |
| 组会 | OpenProject 会议模块 | 议程、纪要、行动项（工作包）、导出 PDF | OpenProject 是完整的项目管理系统（Ruby），只为两三张表部署它太重；它自己的"项目"和平台的项目会重复 |
| 成果 | Zotero 群组文献库 | 有论文、专利、软件三类条目，能存全文、导出引用 | 没有"获奖"类型；不能按年份导出"清单 + 全文"的压缩包；要另开账号。可以作为同学自己管理参考文献的工具，和平台并行 |
| 成果 | VIVO、DSpace-CRIS、EPrints、InvenioRDM | 机构级成果库和知识库 | 面向全校级部署（Java、Solr 等），对一个课题组太重 |
| 成果 | Kiel LitDB（2017 年论文） | 课题组论文库，也记奖项、专利 | 这次没找到它的代码仓库，维护状态不明 |

共同的问题：外部系统都要另配账号和权限，平台的课题组隔离带不过去；每多一个服务，就要多一份部署、升级和备份。三块合计 7 张表，规模和第三期采购相当。

## Alternatives considered

- **知识库用 BookStack，组会和成果自建**：知识库能直接用上成熟的编辑器和搜索。但"新版本保留旧版本"和"按设备找资料"两条验收都要再开发，还要多运维一个 PHP 服务和一个 MySQL，并为它另配登录（平台要先能提供 OIDC，或者学校有 LDAP）。如果以后组里要大量写长篇图文教程，再考虑在菜单里加一个 BookStack 的链接。
- **直接部署 eLabFTW 替代整个平台**：手册第 3 节已否，理由不变。
- **成果用 Zotero 群组库，平台只做导出**：论文录入可以从 DOI 自动取信息。但获奖、软著没有对应类型，年度导出要自己拼，成员还要另注册 Zotero 账号。
- **说明和纪要支持 Markdown**：排版更好。但前端要加 Markdown 渲染和 HTML 过滤两个依赖；第一版先用纯文本。
- **组会附件沿用采购附件的规则（只收 PDF / JPG / PNG，20 MB）**：前端组件现成。但汇报 PPT 是组会附件里最常见的。最初的前端正是这样做的：浏览器走查时看到组会页的上传提示是"PDF、JPG、PNG，单个不超过 20 MB"，文件选择框也只列这三类，于是改为任意类型（后端本来就不限类型）。

## Consequences

- 收益：按设备编号或名称能找到它的 SDK 和手册，设备页直接列出资料；文件旧版本不丢；组会的行动项进了负责人的工作台；年度成果清单和全文一次导出。
- 测试：后端新增 12 个测试函数，覆盖版本号递增与 SHA256、PDF inline / 其他类型下载、作者 / 其他学生 / 管理员的编辑和删除权限、汇报人上传、负责人标完成、成果状态校验、按成员筛选、筛选和导出内容、外组 404 和外组导出为空；抽查四处（"其他类型作为下载""成果修改权限""成果的课题组范围""按成员筛选"）临时改坏后对应测试失败。
- 浏览器（verify-lab，2026-11-17，证据在 `backend/var/verify-evidence/2026-11-17-phase4/`）：
  - 知识库：两个版本的 SHA256 与样例文件一致，PDF 打开、CSV 下载；按 `PA-001` 和"相控阵"都搜得到，搜"电磁"为空；其他学生只读，接口改、传、删都是 403；作者删除 403，管理员有"删除文档"；设备页"资料"列出文档，点进去设备筛选已选好。
  - 组会：汇报人上传 `.pptx`，其他学生的复选框灰掉、写操作 403，下载 SHA256 一致；负责人工作台出现"我的行动项 1"，勾选完成后卡片消失。
  - 成果：表单登记一篇已录用论文并上传全文；另外 4 条对照记录（2026 年已发表、投稿中、2025 年已录用、专利）是用同一接口直接建的，没走表单。筛选"论文 / 2026 年 / 已录用（含已发表）"只剩 2 篇，导出的 zip 里清单 2 行、全文 2 份，SHA256 与上传的文件一致。
  - 外组管理员访问三块的数据和文件全部 404，列表为空；导出返回 200，文件没有打开核对，"外组导出只有表头、没有全文"由后端测试断言。
  - 走查中修了一处：组会附件的提示和文件选择框只列 PDF / JPG / PNG，改为任意类型（`e4786ff`）。修复后看到了新提示，`.pptx` 也上传成功；但 `upload_file` 不受选择框的 `accept` 限制，`accept` 属性本身没有在浏览器里读回。
- 设备并发模型检查：`config/settings.py` 在被覆盖的文件里，这次只在 `INSTALLED_APPS` 加了三个 app，设备代码没动；10 次运行全部符合预期，`SYNC` 更新为 `e4786ff`。
- 没有在浏览器里走的：
  - 有后端测试：编辑组会时保留完成状态、删除文档 / 组会 / 成果、替换和删除全文、成果按成员筛选、知识库按标签筛选、知识库的修改历史。
  - 没有测试：三处的修改历史抽屉（组会、成果的修改历史只有接口，没有测试）、手机宽度、过期行动项标红。
- 权限反例（其他学生改、传、删，作者删文档）是在页面里用 `fetch` 直接发写请求得到的 403，页面上只核对了按钮不出现。
- 代价与风险：
  - **大文件**：SDK 安装包可能有几百 MB，走的是和原始数据一样的上传通道。2 GB 上传和 Nginx 缓存目录的问题在正式部署前一起实测。
  - **搜索**：子串匹配在几千篇以内足够快；文档多了再给标题、说明加 `pg_trgm` 索引（PostgreSQL 自带扩展），不用改接口。
  - **纯文本**：说明和纪要没有图片和格式；主要靠截图记录调试过程的话，需要放附件，或者以后加 Markdown。
  - **导出在服务器上一次打包**：压缩包先放内存，超过 50 MB 转存临时文件，打包期间这个请求一直占着一个工作线程；一年几十篇论文没有问题。
- 回滚：三个新 app 都只新增表；设备详情页的"资料"一栏和工作台卡片删掉即可。
