# Agent Note: 上传头像、填微信号，账号卡片做成飞书那样的名片

Status: implemented

## Problem

- 头像只是姓名第一个字放在蓝色圆里，不能换。用户（2026-11-21）拿飞书的头像菜单做参照："这个布局感觉看着顺眼，然后头像可以上传"。
- "个人信息"弹窗（见 [个人信息和改学号](./2026-11-21-account-profile-and-login-name.md)）把姓名、学号、角色、课题组排成上下两行的表格，空，和别的地方不像；底下"姓名、学号 / 工号在'成员'里自己那一行修改。"是防御性的说明。用户："这个界面太丑了……防御性的字去掉"。
- 看了方案后用户又说："学号 / 工号这几个字根本没必要，直接一个圆角标签"，"更换头像是点击头像，不是按钮"，"设计能不能简洁优雅"。
- 联系方式只有邮箱和电话。用户："搞个微信号吧，感觉这个在国内这个比较重要"。

## Decision

- **账号卡片**（`layouts/AccountCard.vue`，账号菜单顶部 48px、"个人信息"顶部 64px 共用）：
  - 左边 `el-avatar`：有照片显示照片，没有是蓝底白字的姓名首字。
  - 右边第一行是姓名，后面跟一个灰色胶囊标签写学号 / 工号，不加"学号 / 工号"字样；第二行次要文字"角色 · 课题组"。
  - 侧栏顶部按钮里的 32px 头像也显示照片。
- **"个人信息"弹窗**：顶部是账号卡片，一条分隔线，下面两列四个输入框：邮箱、电话、微信号、研究方向。去掉"找谁改"的说明。
- **换头像**：在"个人信息"里点头像本身（右下角一个白色小相机图标，触屏上也看得出能点），不另放按钮。选完立刻上传并生效，不用点"保存"。不提供"移除头像"：换一张即可。
- **浏览器里裁剪**（`utils/image.ts`）：取图片正中间的正方形，缩成 256×256 JPEG（透明处填白），一般几 KB 到二三十 KB。后端因此不用装图片库（项目没有 Pillow）。浏览器读不出来的文件（例如 HEIC）提示"只支持 JPG、PNG、WebP 图片"。
- **存储和接口**：
  - `User.avatar` 文件字段，存储名由服务器生成（`avatars/<uuid>.jpg`），和其他上传文件一样走 Django 的存储接口（本机目录或 NAS），备份时一起带走。`User.wechat` 最长 50 字。两个字段在同一个迁移 `0005`。
  - `GET /api/auth/me/avatar/` 返回本人头像，没有就 404。`POST` 只收 JPG、PNG、WebP，最大 2 MB，用 `core.files.checked_upload` 检查。
  - 上传时锁住本人这一行；被替换的旧文件在事务提交后删除，保存失败时删掉刚写入的新文件（和成果全文同一个写法）。
  - 未改初始密码时 `POST` 返回 403 `password_change_required`。
  - `/api/auth/me/` 返回 `avatar_url`，URL 带存储名做版本号，所以换了头像浏览器不会继续显示缓存的旧图。
- **微信号**：本人在"个人信息"里改，管理员在"成员"、运维在"系统管理 → 账号"的编辑弹窗里也能改。微信号和电话一样算私密字段（`PRIVATE_FIELDS`）：导师和管理员在"成员"列表里多一列"微信号"，学生看不到别人的。
- DESIGN.md：
  - 布局一节写了账号卡片和"点头像换照片"。
  - 表单一节删掉"用一行次要文字说明找谁改"，改成"不写防御性的说明"。

## Alternatives considered

- **装 Pillow，由后端裁剪、压缩并确认是图片**：后端最稳，但要多一个带 C 扩展的依赖，Docker 镜像也要改。现在后端只收三种图片扩展名，按扩展名返回图片类型，浏览器也不会自己猜测内容类型（SecurityMiddleware 默认 `nosniff`），所以即使绕过页面传上来别的东西，也只会被当成一张显示不出来的图片。设备使用登记的照片也是这样处理的。
- **"更换头像""移除"两个按钮**（第一版方案）：用户否掉了，要点头像本身。
- **卡片上写"学号 / 工号 mgr"、姓名旁放铅笔**（第一版方案）：用户觉得啰嗦。登录名做成标签本身就分得清；"个人信息"就在卡片下面，铅笔是重复的入口。
- **可拖动、缩放的裁剪框**：选图更准，但要写一个裁剪组件或加新依赖。先只取中间；想要别的位置可以在手机上裁好再传。
- **在成员列表、审批、周报里显示别人的头像**：要另开接口、按课题组判断谁能看，还要改好几个页面，这次没有要求。以后做就加 `/api/members/<id>/avatar/`。
- **学生注册时填微信号**：注册表单再长一行；登录后在"个人信息"里补也一样。

## Consequences

- 在"成员"页打开自己的"个人信息"改了微信号，列表要切换页面或刷新后才更新（弹窗不通知列表）。
- 后端只看扩展名、不看内容；iPhone 的 HEIC 照片要先转成 JPG。
- 验证：
  - 后端测试：上传后能取回，类型是 `image/png` 且带 `nosniff`；再传一张 URL 变了、旧文件被删；`.svg` 400，超过 2 MB 413，未改初始密码 403。本人、管理员能改微信号；学生看不到别人的微信号。
  - 前端测试："个人信息"只提交四项；点头像打开选文件，选完直接 `POST` 头像，不发 `PATCH`。
  - 浏览器（验证实例，`mgr`，1440 宽和 390 宽）：账号菜单和弹窗的样子；用一张 600×400、左右涂红的图片上传，存下来是 256×256 JPEG（5.7 KB），左右边缘是蓝色（取的是中间）；侧栏、菜单、弹窗三处同时换图，刷新后仍在；`.heic` 提示只支持三种图片、头像不变；微信号保存后在成员列表里显示。
