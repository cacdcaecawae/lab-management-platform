# Agent Note: 学生自助注册：凭课题组注册链接申请，管理员逐个或一键审核

Status: implemented

## Problem

现在账号只能由人开：运维在"系统管理 → 账号"开管理员和导师，管理员在"成员"里一个个开学生，批量只能在服务器上运行 `import_members`。开组时管理员要逐个录入学号、姓名，再把初始密码分别发给每个人，学生第一次登录还得改一次密码。全组约 70 人，这一步最费事。

2026-11-20 用户提出改成学生自己注册、管理员审核（可一键通过），参考 sub2api；同日确认了下面的方案。

sub2api 的做法（源码 `backend/internal/service/auth_service.go`、`domain_constants.go`）：运维打开"开放注册"后任何人都能注册，可选邮箱验证码、邮箱后缀白名单、一人一个用过作废的邀请码；注册后立即可用，不经审核，因为新用户余额是 0，什么也用不了。这里不一样：学生一进组就能看到全组的设备、组会、知识库和成员名单，所以必须先审核。

## Decision

**注册链接**：

- 每个课题组一个注册码，存在 `ResearchGroup.signup_code`（12 位随机，`secrets.token_urlsafe(9)`），空表示关闭。管理员在"成员"页顶部的卡片打开开关"允许学生用链接注册"，页面显示 `<网址>/register?code=<码>`、"复制链接""换一个链接"。关闭和换链接都先确认，旧链接随即失效。接口 `GET/POST /api/members/signup/`。
- "复制链接"先用剪贴板接口；内网 HTTP 页面没有这个接口，改为选中输入框里的文字再用旧的复制命令；这个命令也失败时提示"浏览器不允许自动复制，链接已选中，请按 Ctrl+C 复制"，不报"已复制"。

**注册**（`POST /api/auth/register/`，匿名、要 CSRF）：

- 整个注册在一个事务里，先按提交的注册码锁住课题组那一行（`select_for_update().filter(signup_code=code)`）。管理员关闭或更换链接要改同一行：要么等这次申请提交完，要么先改完、这次申请就找不到匹配的组。
- 找不到就 400（`errors.code`："注册链接已失效，请向课题组管理员要新的链接"），不看其他字段，外人不能借此试探哪些学号已有账号。码对了再用 `NewAccountMixin` 校验：学号重复 409、密码按 Django 规则、姓名必填。
- 只建学生：`role=student`、`is_active=False`、新字段 `User.pending=True`、`must_change_password=False`（密码是学生自己设的）。表单里别的字段（角色、课题组、启用）一律忽略。
- 每组最多 30 个待审核，满了 409 `too_many_pending`；在上面那把锁里数，两个并发申请不会一起越过上限。同一来源地址每小时 10 次（`RegisterRateThrottle`，地址取法和登录限速相同）。
- 在同一事务里给本组管理员发站内通知"<姓名> 申请加入课题组，请审核"，链接到 `/members`。
- 前端 `/register` 是公开页面；没有码只显示"注册要用课题组管理员发的注册链接打开，请向管理员索取。"。登录页底部加一行"还没有账号？打开课题组管理员发的注册链接申请。"

**等待审核**：待审核账号登录时，密码对才返回 403 `pending_approval`"账号正在等待管理员审核，通过后才能登录"；密码错仍是"用户名或密码错误"。

**审核**（本组管理员）：

- 卡片里"待审核（N）"表格（姓名、学号、邮箱、申请时间）可勾选；"通过""拒绝"作用于勾选的行，"拒绝"和"全部通过"先确认。接口 `GET /api/members/pending/`、`POST /api/members/approve/`、`/reject/`，参数 `{ids}`（1–100 个），返回 `{count}`；只处理本组待审核的账号，其他编号忽略。
- 通过：`is_active=True`、`pending=False`。拒绝：删除账号（从没登录过、没有数据），同一学号可以重新申请。拒绝在事务里先 `select_for_update` 锁住仍待审核的那几行，再按这些编号删除；另一位管理员同时"通过"时，要么先通过（这一行不再匹配、不删），要么等删除提交（通过 0 人）。原来直接用查询集删除：Django 先查出要删的行、最后才按主键删，中间被别人通过的账号也会被删掉。
- 运维在"系统管理 → 账号"里看到"待审核"标签。
- **待审核的一定是未启用的学生**：数据库约束 `pending_is_inactive_student`（`pending=false` 或 `is_active=false 且 role=student`）。`User.save()` 里，待审核账号被启用或改成别的角色时自动清掉 `pending`，所以运维在"系统管理"或 `/admin/` 启用它就是通过，改成导师就离开审核列表、成为一个未启用的导师账号；管理员的"通过""拒绝"再也碰不到它。约束兜住绕过 `save()` 的批量更新。

**待审核的人不是成员**：

- 成员列表、详情、修改、重置密码的查询都加 `pending=False`，对待审核账号一律 404；审核动作只看 `pending=True`。
- `AnyGroupMemberField`（组会主讲人和行动项负责人、成果成员）原来连停用的成员都收，改成排除待审核的。其余选人和提醒（项目成员、任务负责人、周报未交名单、通知、提醒邮件）本来就只取 `is_active=True`，不受影响。

**不做**：邮箱验证码、审核通过后发邮件、二维码、全站统一的注册开关。

## Alternatives considered

- **照搬 sub2api，注册后立即可用** — 最简单。但新学生一进来就能看到全组共享的数据，网站放到公网后任何拿到链接的人都能进来。
- **公开的注册页，下拉选择课题组** — 不用发链接。但会暴露所有课题组的名字，任何人都能往任意组投申请，管理员要处理陌生人的申请。
- **一人一个邀请码（sub2api 的邀请码）** — 不需要审核。但管理员要先为每个学生生成一个码再分别发，和现在一个个开账号差不多费事。
- **网页上导入 Excel 名单** — 管理员一次导入全组，不用审核；开发手册原本就是这么写的。但学生仍要拿初始密码、再改密码，名单也要管理员整理。两者不冲突，以后可以再做。
- **待审核状态复用 `is_active=False`、不加字段** — 少一次迁移。但就分不清"待审核"和"已停用"：停用的成员会出现在待审核列表里，被误拒绝时账号连同数据一起删掉。
- **注册码用 DRF 字段校验** — 写法统一。但 DRF 会把所有字段的校验都跑完，学号重复的 409 会先于注册码错误抛出，泄露学号是否存在；所以在视图里先核对注册码。

## Consequences

- 迁移 `accounts/0004_signup` 加两个字段，默认值不改变已有账号。
- 链接被转发到组外，陌生人也能提交申请，靠管理员核对学号和姓名挡住；"全部通过"会把所有申请一起放进来。
- 处理完申请后，管理员铃铛里的那几条"申请加入"通知仍是未读，要自己点掉。
- 匿名接口靠注册码、限速和每组 30 个上限控制，没有验证码；被刷时管理员可以关掉或换链接。
- 验证：
  - 后端 12 个测试：申请到通过、登录提示、链接关闭 / 更换 / 错码不泄露学号、表单校验和忽略多余字段、CSRF、待审核的人不出现在成员接口且选不进成果和项目、外组和非管理员无权、30 个上限和每小时 10 次、运维启用即通过；运维改角色或 `save()` 启用后不再待审核，数据库拒绝违反约束的批量更新；两位管理员同时通过和拒绝同一申请（PostgreSQL，两个连接）只有一方生效；注册进行中关闭链接，关闭先完成就不会建出申请。"选不进成果"在撤掉 `AnyGroupMemberField` 改动后会失败；后三条是 PR 审查（`59b731f`）提出的，在当时的代码上都失败。
  - 前端：注册页（无码、提交、密码不一致、服务器报错）、注册卡片（链接显示和关闭、勾选通过、全部通过和拒绝要确认）、接口契约。
  - 浏览器（隔离实例，`verify-lab` 的 `signup.md`）全部子功能走通，数据库读回一致；走查中补了开关的无障碍名称，并把"返回登录"从链接套按钮改成普通链接。"复制链接"没有读回剪贴板；后备复制失败时的提示由前端测试覆盖。
