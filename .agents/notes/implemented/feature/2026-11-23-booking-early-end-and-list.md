# Agent Note: 预约可以提前结束、有列表视图，扫设备码直达使用登记（issue #48 N3）

Status: implemented

## Problem

- 预约用完提前离开，剩下的时段仍被占着；别人只能等，或者找管理员取消（取消后又没法登记使用）。
- 预约页只有日历。想查自己以前的预约、哪些还没登记使用，只能一周一周翻；接口按时间窗口查询，最多 62 天。
- 扫设备二维码打开设备详情后，要登记本次使用，还得再去预约页找那条预约。
- 相关决定：[预约并发的 TLA+ 模型](../testing/2026-11-17-tla-equipment-booking.md)、[第二期设备与耗材](./2026-11-17-phase2-equipment-and-consumables.md)。

## Decision

- **提前结束** `POST /api/bookings/{id}/end-now/`：
  - 预约人或管理员；只对正在进行（`start_at <= now < end_at`）、未取消、没提前结束过的使用预约，否则 409 / 403。只能结束一次：开始一分钟内结束的预约在那一分钟里仍在进行，再结束一次会把原定结束时间盖掉。
  - 锁住预约行后改 `end_at`：现在取整到分钟，但至少比开始晚 1 分钟（结束必须晚于开始），也不会比原来晚。只缩短、不延长，所以不会和别的预约重叠；数据库排他约束照旧兜底，正在建重叠预约的事务会等它提交。
  - 原来的结束时间记在新字段 `Booking.planned_end_at`（迁移 `equipment/0005`），预约详情写"提前结束，原定到 HH:MM"。预约没有修改历史表，这一列就是记录。
- **列表视图** `GET /api/bookings/all/`：分页、按开始时间倒序、不受 62 天窗口限制；日历仍走原来的窗口查询。
  - 筛选：只看我的、待登记、设备、开始日期范围。
  - "待登记"和工作台"待登记使用"用同一个查询 `equipment.queries.awaiting_report`（已结束、14 天内、没有使用登记的使用预约），工作台不再自己写一份。
  - 预约页的视图切换加"列表"，日历只是隐藏，切回去还在原来那一周；工作台的链接用 `?view=list&pending=1`。
- **扫码登记**：设备详情页查 `reportable=1`（自己在这台设备上已开始、14 天内结束、还没登记的使用预约）。有就把主按钮换成"登记本次使用"，打开的就是 `/bookings?booking=<id>`，登记表单和权限都复用预约详情。
- **模型检查**：`spec/EquipmentBooking.tla` 加了"提前结束"请求（`EndStart`、`EndLockBooking`、`EndUpdate`），两条新规则：
  - `NoOverlap`：同一设备未取消的预约不重叠，提前结束的不再占着自己时段的剩余部分。
  - `EndsOnlyStartedUse`：只有已开始的使用预约能提前结束。
  - 新的变体 `break-end-skips-started-check` 去掉"已开始"的检查，规则 7 随之失败；其余 10 次运行结果和以前一样。

## Alternatives considered

- **提前结束 = 取消 + 新建一条到现在为止的预约**：不用新接口；但两步之间别人可能约进来，还丢了使用登记的关联。
- **刚开始一分钟内结束就直接取消**：没有一分钟长的预约；但学生不能取消已开始的预约，这里会变成绕过那条规则；而且已登记的预约不能取消。改为至少保留 1 分钟。
- **列表视图在前端把日历的多个窗口拼起来**：不改后端；但查一年前要发很多请求，分页和筛选也做不好。
- **设备详情直接内嵌一个登记表单**：少跳一次；但登记要校验"这条预约是不是你的、能不能登记"，复用预约详情那一套更不容易出错。
- **给预约加修改历史（`HistoricalRecords`）来记提前结束**：能记下谁、什么时候；但只为这一个动作多一张历史表，一列 `planned_end_at` 就够说明原来到几点。

## Consequences

- 测试：`equipment/tests/test_end_now_and_list.py`（提前结束后别人能约上剩下的时间、谁能结束哪些预约、开始一分钟内结束保留 1 分钟且不能再结束一次、列表视图的筛选和"待登记"与工作台一致、外组看不到）；前端 `BookingsView.test.ts` 加了"提前结束"。
- `verify-equipment-tla`：11 次运行都符合预期；同步点在这次提交后更新。
- 结束时间取整到分钟：同一分钟里新建的预约如果开始时间早于那一分钟，仍会被判为重叠（409），换个时间即可。
- verify-lab 的 `equipment.md` 已更新。
