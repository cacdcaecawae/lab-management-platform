# Agent Note: 存储用量统计

Status: implemented

## Problem

人工执行 du 无法解释课题组或模块对数据盘的用量贡献，也会将磁盘上其他文件视作平台文件。

## Decision

- 运维在系统管理 → 存储看全平台账面：对当前带文件路径的数据库记录汇总已知字节和大小未知记录数，不扫描文件和对象桶。
- 课题组按模块汇总原始数据、知识库各文件版本、组会、采购报销、成果全文、设备使用照片。按现有权限口径归属；无组归在「未分配课题组」。设备登记及后台更换照片时记录字节数（清除照片时同时清空字节数，元数据不可手填），历史照片和成果全文的大小仍为未知，不发起存储读取。
- 最近 12 个自然月含本月，按北京时间与上传日期划分，只统计现在仍在账、大小及上传日期已知的文件。设备照片的首次上传和更换均记录本次写入时间，清除同步置空；历史照片不借用登记日期，已知字节仍计入总量。它不是过去上传总量，也不是净增长。最近 3 个完整月份都有已知文件时，乘 4 粗估同口径一年字节；缺月份不推算，从不输出磁盘尚可用多久。零字节文件属于已知。
- 默认 Django 上传存储是文件系统时，可独立展示其挂载卷容量（含非平台文件）；路径不可用或非文件系统时不以本机盘冒充容量。
- 管理员与导师可从成员页看本组原始数据按上传人和项目的两个汇总；外组成员和项目身份不会出现在位置表中，历史移动/异常关联归未归属。运维无组不能调用本组接口。依赖不下沉到系统 app。

## Alternatives considered

- 实时扫描文件或逐个调用 storage.size：若文件很多会显著增加等待，还会访问实际存储。
- 预计磁盘耗尽时间：文件清单无法解释磁盘净增长、已删除数据与未知大小，因此不报告。
- 定期保存物理变化样本：可为后续真实容量规划提供数据，不作为本次只读报表的隐含承诺。

## Consequences

- 北京时间月界、已知/未知字节、缺月停止外推、组权限、外部身份折叠、本地/非本地报告已由隔离 PostgreSQL 测试验证。
- 前端有运维对象存储回退与本组汇总组件测试。真实浏览器验收另列，不以组件测试代替。
