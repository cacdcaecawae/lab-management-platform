# Agent Note: 平台叫 Phase，没登录时打开网站看到首页，登录在弹窗里

Status: implemented

## Problem

- 没登录时打开网站，只有一个登录框，上面是蓝底的"课"字和"课题组管理平台"。第一次拿到链接的学生不知道这是什么、能做什么。
- 用户和 Fable 做了首页原型（`backend/var/login-proto/phase2.html`，由同目录 `build_phase2.py` 生成），要求（2026-11-22）："这个是我和fable做的首页……也放入本次的版本中"。
- 原型的内容：
  - 顶栏只有标志和名字 Phase，大按钮滚出屏幕后，顶栏右边出现"登录"。
  - 首屏一个会动的玻璃环（WebGL），下面是大字 Phase、黑色"登录"按钮和一句"科研资料存得住，课题组日常管得清。"。
  - 下面两张卡片：一张讲科研资料（知识库文档的版本、配置每日加密备份后的恢复），一张讲日常事务（十个应用图标，个人记录只有本人、导师和管理员看得到）。
  - 点"登录"弹出原生 `<dialog>`：标志、"登录 Phase"、学号 / 工号和密码两个浮动标签输入框、黑色"登录"按钮、"还没有账号？打开课题组管理员发的注册链接申请。"。
  - 不支持 WebGL 时换成静态图；玻璃环滚出屏幕或切到别的标签页就停止绘制；系统设置了"减少动态效果"时不动。
- 原型叫 Phase，系统里其余地方都叫"课题组管理平台"。问用户只改首页还是全站改名，用户（2026-11-22）："叫 phase 啊，这是起的我们课题组的名字，后面开源，他们想改啥改啥，我就叫这个啊"。

## Decision

- **名字**：全站叫 Phase。浏览器标签标题、`/admin/` 页头（"Phase 后台"）、邮件标题（"[Phase] 今日提醒""[Phase] 测试邮件"）、邮件正文里的"请登录 Phase"、README 标题一起改。仓库名、包名不动。
- **页面**：`LoginView.vue` 换成原型的首页，地址仍是 `/login`。文字、图片、排版和三档窄屏布局照搬原型：
  - 玻璃环的 WebGL 代码原样移到 `views/home/glass.ts`（`drawGlass` 返回停止函数，画不了时返回空），`GlassRing.vue` 负责挂上画布、画不了或 GPU 丢了上下文时换静态图。离开首页时停止绘制并释放 GPU 上下文。原型里截图用的 `?at=`、`?tilt=` 参数没有搬。
  - 两张卡片的图由脚本从原型原样复制成 `HomeFiles.vue`、`HomeApps.vue`。
  - 图片由原型用的 1024px 渲染图缩出：`assets/phase-icon.png`（128px，28 KB，顶栏、登录框、注册页、改密码页、浏览器标签图标）和 `assets/phase-ring.webp`（768px，145 KB，只在画不了时才加载）。
- **跳过首页的情况**：
  - 已登录的人不会看到首页（路由守卫照旧送去工作台）。
  - 带着 `next` 进来（登录过期，或者点了通知、邮件里某一页的链接）时直接打开登录框，登录后回到那一页。只打开网站地址时停在首页：守卫原来把 `/` 写成 `next=/`，`postAuthTarget` 现在不接受工作台（登录后本来就去工作台）。
- **登录框**：原生 `<dialog>`（Esc 关闭、焦点留在框里、背景模糊都是自带的），提交走 `auth.login`。比原型多了两样：登录失败时框里一行红字显示后端的原因（密码错、账号待审核等），登录中按钮变灰、写"正在登录…"。框里的内容填满对话框，只有点到外面的模糊背景才关闭（原型点框内空白处也会关）。
- **颜色和字号**：白底、超大字号、卡片阴影、黑色按钮只在首页用，写在页面自己的样式里；文字颜色、焦点蓝、错误红用 `theme.css` 的变量。原型的浅灰字 `#86868b` 换成 `--lab-text-3`（DESIGN.md 要求文字对白底至少 4.5:1）。DESIGN.md 加了"首页"一节。卡片的类名不能叫 `.card`：`theme.css` 给相邻的 `.card` 加了上边距，第一次截图时右边卡片低了 16px。
- **注册页、改密码页**：结构不变，蓝底"课"字换成新标志。

## Alternatives considered

- **只换首页样式，其余还叫"课题组管理平台"**：用户否了，Phase 是课题组起的名字。
- **保留现在的登录框，首页另放在 `/`**：要多一个公开路由，`/` 现在是登录后的工作台，登录过期时的跳转也要分两种。只用 `/login` 一个地址更简单。
- **登录框用 Element Plus 的 `el-dialog`（DESIGN.md 的共用弹窗）**：系统里的弹窗是编辑表单用的，样子和原型的大圆角居中卡片不同；原生 `<dialog>` 已经处理了焦点和 Esc。
- **去掉玻璃环动画，只放静态图**：最省电，但这是原型最主要的东西；已经有停绘和静态图兜底。

## Consequences

- 每天用的人没登录时要多点一下"登录"。会话 14 天有效，平时已登录直接进工作台；从某一页跳过来时登录框直接打开。在工作台上登录过期的，回到的是首页（没有 `next`）。
- 首页按功能说明文件留存范围。运维需要配置并检查每日加密备份。
- 老电脑的集成显卡上，玻璃环会占一些 GPU；只在首页、在屏幕上、标签页在前台时才画，GPU 慢时先降分辨率。
- 首页的 JS 是 45 KB（gzip 12 KB），路由懒加载，进系统后的页面不带它。
- 验证：
  - 前端测试（`LoginView.test.ts`）：直接打开不弹框、点"登录"弹框；`next=/` 不弹框；带 `next` 自动弹框，登录后去那一页；登录失败框里显示原因，再登录去工作台。`router.test.ts` 加了 `/` 不算返回目标。
  - verify-lab 浏览器（证据在 `backend/var/verify-evidence/2026-11-22-login/`）：1440、1000、390 宽截图和原型一致；390 宽滚动后顶栏出现"登录"；`s_b` 密码错时框里红字"用户名或密码错误"，`s_a` 登录进工作台；打开 `/datasets` 跳到 `/login?next=/datasets`、框已打开，`s_b` 登录后回到 `/datasets`；把 `getContext` 换成返回空时显示静态图；注册页显示新标志；标签页标题是 Phase，构建后的 `index.html` 引用打包后的图标。
  - 后端测试全部通过（邮件标题没有测试断言名字）。
  - 浏览器自动化场景的 `submit_login` 改成先点首屏"登录"再在框里登录；这些场景只在指定分支的 CI 上跑，这次没有跑。
