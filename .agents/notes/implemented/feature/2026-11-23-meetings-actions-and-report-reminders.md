# Agent Note: 一键催交周报，组会行动项跨期跟踪，导师也能建组会，新组会延续未完成事项（issue #48 N4 余下）

Status: implemented

## Problem

- N4 的周报部分已由 PR #52 完成：汇总、导出、下一份待反馈、带入上周计划、本周已有直接打开。还差：导师在"未交名单"里看到谁没交，只能一个个去催。
- 组会：
  - 行动项散在每次组会里。上周、上上周的事项完成了没有，要一次次点开旧组会看；没有一页能按人看全部未完成事项。
  - 只有管理员能新建、编辑组会；导师自己主持组会时也要找管理员录。
  - 每次新建组会都要把上次没做完的事项重抄一遍，纪要也没有固定格式。
- 相关决定：[第四期知识库、组会、成果](./2026-11-17-phase4-knowledge-meetings-achievements.md)、[周报汇总与科研记录效率](./2026-11-23-research-and-reports-efficiency.md)、[角色和身份分开](../architecture/2026-11-23-roles-and-identity.md)。

## Decision

- **一键催交**：`POST /api/reports/remind-missing/ {week_start?}`，只给导师。
  - 给该周未交名单里的每个人发一条站内通知"请提交 <周一> 这一周的周报"，链接到周报页。
  - 平台启用了邮件时再发一封，收件人放在密送里（彼此看不到地址）；发信失败只记日志，不影响通知。为此 `core.mail.send` / `send_quietly` 多了 `bcc` 参数。
  - 同一人、同一周一天只提醒一次：发之前查当天是否已有同标题的通知，返回 `{reminded, already}`。
  - 每日提醒邮件里原有的"未交周报"不变。
  - 周报页的 `?tab=`、`?week=`、`?status=` 跟着地址，工作台的链接可以直接打开某一周的未交名单。
- **行动项总览**：`GET /api/action-items/?open=&overdue=&owner=`（本组、分页），按截止日期（没有的在后）、组会日期倒序。组会页加"行动项"标签（`?tab=actions`），默认只看未完成；勾完成走原来的接口，负责人和管理员可以勾（[#58 P4](./2026-11-25-projects-reports-meetings-polish.md) 起导师也可以）。
- **导师也能新建、编辑组会**：写权限从"管理员"放宽到"导师或管理员"（`IsSupervisor`），删除组会仍只限管理员；附件上传和删除同样加上导师。
- **新建组会时延续**：
  - 新建页的"带入上次未完成的事项"把最近一场组会还没完成的行动项抄进表单，负责人、内容、截止日期照旧，可以再改。每行带着 `carried_from`。
  - 保存时，后端把这些旧事项记为完成（`done_at`），并记下转入了哪场（新字段 `ActionItem.carried_to`，迁移 `meetings/0002`）。旧组会里那一条显示"已转入 <日期> 组会"，不能再勾；总览的"未完成"里也不再出现。删掉新组会时，转入它的旧事项恢复成未完成，不会随新组会一起消失；但组会里有事项已经再转入后面的组会时不能删（409，写明转到了哪天），否则删掉后原事项和后面的副本都是未完成。要从最新的往前删。保存时先锁住要带入的旧事项：两个人同时新建组会带入同一条，后保存的那个返回 409（"已经完成或转入别的组会"）；要带入的事项已经不在（所在组会被删了）也返回 409，不会多出一条未完成的副本。勾选完成也先锁住这一条，和结转按先后生效。同一个人既有带入的事项又有新事项时，照常收到新事项的通知。新的那条记下它从哪条带入（`ActionItem.carried_from`，迁移 `meetings/0003`）：编辑组会时删掉这一行，原来那条恢复成未完成（这一行已经再转入后面的组会时同样 409）；同一次保存里同一条带入两次、或已有的行带 `carried_from`，返回 400。只能带入日期不晚于这场的组会的事项（400）：补录旧组会时，页面取这场日期及以前的最后一场（`?before=`），不会把后面组会的事项关掉。Django 后台不能删除涉及带入的行动项或组会（单个删除和批量删除都不行），要删就从网站上删，网站会把事项接回去，或者拒绝删除。后台也不能改已转出事项的完成状态（否则原件和副本都成未完成）。带入总是从早到晚：改组会日期（网站和后台）时，不能早于带入来源的组会，也不能晚于转入去的组会。
  - 带过来的事项不再给负责人发"有新的组会行动项分配给你"。
  - 纪要框预填"本周进展 / 讨论 / 决定 / 下周安排"，模板写在前端，不存数据库。

## Alternatives considered

- **催交自动定时发**：不用导师点；但每日提醒里已经有"未交周报"，再自动催容易变成骚扰。由导师决定什么时候催。
- **行动项"移动"到新组会（而不是复制）**：一条事项只有一份；但会改掉旧组会的记录，旧纪要里的事项就消失了。复制并在旧的那条记下"已转入"，两场组会的记录都完整。
- **转入的旧事项只标完成、不记去处**：不用新字段；但旧组会里看不出它是做完了还是转走了。
- **组会编辑仍限管理员，导师通过管理员录入**：保持现状；但 issue 已确认要放开给导师。
- **每封催交邮件单独发**：收件人互不可见；但几十个人就要连几十次 SMTP，请求会很慢。改为一封密送。
