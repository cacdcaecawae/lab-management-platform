# Agent Note: 采购、到货、入库、建设备、报销串起来（issue #48 N2；N1 预算不做）

Status: implemented

## Problem

- 采购到货以后，入库、登记设备、报销都要换页面重填一遍。报销关联了采购申请，经费、金额、说明还是手填。
- 低库存的耗材要发起采购，得自己到采购页从头写品名和规格。
- 报销只能一条一条交财务、标到账；采购列表不能导出。
- 相关决定：[第三期采购与报销](./2026-11-17-phase3-procurement-and-reimbursement.md)。

## Decision

- **低库存 → 采购**：低于安全库存的耗材，"库存"后面有"发起采购"，打开新建采购申请（`?name=&spec=&quantity=`），第一行明细填好品名、规格，数量 = 安全库存 × 2 − 当前库存，至少 1。预填不算未保存的修改。
- **到货后的三个入口**（已到货的采购详情）：
  - "入库到耗材"（管理员）：打开耗材页（`?purchase=&code=`），顶上提示"为 PR-… 入库"，在任一耗材点"入库"时采购申请已选好。到货的是哪种耗材由管理员选。
  - "登记为设备"（管理员）：打开新建设备（`?new=1&purchase=&code=&name=`），名称是第一行明细，采购申请已选好。
  - "发起报销"（申请人）：打开登记报销（`?purchase=`），关联这张申请并自动填写。
- **报销自动填**：在"关联采购申请"里选了一张（或从"发起报销"进来），填经费来源、金额（采购合计）、说明（用途，截到 200 字）。一个字段和打开时不同、也不是上次自动填的值，说明是人改过的，不再覆盖。
- **报销批量**：列表可以多选，"交财务"或"标到账"（只限管理员）。`POST /api/reimbursements/batch-advance/ {ids, status}`：每笔单独锁行、单独走和单笔一样的检查（同一个 `move()`），做不了的列出编号和原因（缺发票、状态不对、不是自己的），其余照常完成。
- **采购导出**：`GET /api/purchases/export/`，与列表同样的范围、筛选、搜索和排序。

## Alternatives considered

- **经费来源加预算和余额（issue 的 N1）**：导师批采购时能看到这笔经费还剩多少；但用户 2026-11-23 决定不要预算。经费仍只做统计、不控制额度，也不显示余额。
- **到货后自动生成设备和入库记录**：少点几下；但第三期已决定"不按明细自动生成台账"（一条明细可能是多台设备、也可能不入库），这里只预填、不自动建。
- **批量操作整批一个事务，有一笔不行就全不做**：结果简单；但一笔缺发票就挡住其他十几笔，用户要先找出是哪笔。改为每笔单独，结果里列出没做成的。
- **"入库到耗材"自动选中一种耗材（按品名匹配）**：少点一下；但品名和耗材名常写得不一样，猜错了入库到别的耗材更麻烦。

## Consequences

- 测试：`procurement/tests/test_chain.py`（批量交财务时缺发票的列出、看不到的列为不存在；只有管理员能批量标到账；采购导出跟着列表的排序和范围）；前端 `ReimbursementsView.test.ts`（从采购单发起报销时自动填写）。
- 批量操作中途失败不回滚已成功的笔数，结果里写清哪些没做成。
- 设备表单多了一个只用于新建的 `initial`（名称和采购申请），编辑时不用；打开时记值、只提交改了的字段、带 `status_seen` 都没变。
- verify-lab 的 `procurement.md`、`reimbursements.md`、`consumables.md` 已更新。
