# Agent Note: 设备与试件二维码标签

Status: implemented

## Problem

要预约设备、查手册或登记试件借用，过去需要先打开平台台账，再按实物上的编号查找。扫码应直接打开对应详情，但不能绕过登录、首次改密或课题组权限。

## Decision

- 二维码只编码当前浏览器 origin 加现有设备/试件详情路径，不包含名称、缺陷、令牌或其他数据，不调用第三方生成服务。打印页提示必须在稳定的正式域名下先少量试印。
- 管理员可从台账选择本页多条，或从单件详情打开打印页。打印页仅管理员可打开，但二维码目标仍是原来的组内详情，正常组员可扫码访问，外组查询仍由原 API 权限拦截。
- 打印页复用现有查询权限，不加后端 API。每批最多 96 个正整数 ID，去重并保留顺序，每次并发读取最多 6 项；加载失败不打印部分结果。前端用 `qrcode` 生成 PNG，A4 每页 3 列 × 8 行，标签只显示编号、名称和二维码。
- 登录、首次强制改密和会话失效会保留合法的站内业务地址；外部地址及登录、改密等中转页不会用作回跳目标。目标页面正常跑原有路由权限检查。

## Alternatives considered

- 只打印编号无法省掉人工搜索；后端生成增加接口和缓存，不必要。可换域名的短码需要另建跳转和映射表，当前先等稳定域名再批量打印。

## Verification

- Vue 测试覆盖两类详情地址、标签内容、A4 分页、非法参数、失效请求、查询失败、登录和首次改密回跳及角色门禁。
- 真实打印预览和实物手机扫码按 [labels.md](../../../../.claude/skills/verify-lab/features/labels.md) 走查；在正式域名就绪前不得宣称实体标签已验收。

## Consequences

部署地址变化会让已印的二维码失效；不要用本地或临时地址批量打印。打印模板的边距依打印机而异，先小批核对大小、对比度及手机识别；设备/试件会接触油或耦合剂时应选耐用标签纸。
