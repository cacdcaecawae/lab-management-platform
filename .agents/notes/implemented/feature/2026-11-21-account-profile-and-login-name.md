# Agent Note: 头像菜单里的个人信息、管理员和运维在页面里改学号 / 工号

Status: implemented

## Problem

- 头像菜单只有"修改密码""退出登录"。`/api/auth/me/` 只能读：本人改不了自己的邮箱、电话、研究方向，只能找管理员在"成员"页改；每天的提醒邮件发到登记的邮箱，填错了本人也改不了。
- 学号 / 工号就是登录名。学生用注册链接申请时自己填（见 [学生自助注册](./2026-11-20-student-self-signup.md)），管理员审核时看得到但不能改；通过后，"成员"和"系统管理 → 账号"的编辑弹窗里这一栏是灰的，接口也只读。填错了只能让运维进 Django 后台（服务器本机 8091 的 `/admin/`，要建 SSH 隧道）改。用户（2026-11-21）要求"让我们都能改，不是从后台改"，并要保持现有界面风格、同步更新 DESIGN.md。

## Decision

- **改学号 / 工号**：`LoginNameMixin`（`accounts/member_serializers.py`）给成员编辑（`MemberSerializer`）和运维账号编辑（`system` 的 `AccountSerializer`）共用：`username` 改为可写，格式检查和新建一样（Django 的用户名规则），已被任何账号（任何课题组、含运维）使用 → 409 `conflict`，并发抢同一个名字时数据库唯一约束兜底也是 409。谁能改沿用原来的范围：管理员改本组学生和自己，运维改所有课题组账号（不含运维账号）。本人在"个人信息"里不能改。记录、预约、审批都关联账号 id 而不是登录名，改了只影响下次登录用哪个号；已登录的会话不受影响。
- 重名的提示统一成"这个学号 / 工号已经有账号在用"（`LOGIN_NAME_TAKEN`，新建、改名、学生注册三处），不再说"用户名"。前端 `useFieldErrors` 加第二个参数：指定 409 属于哪个字段，学号重复时错误显示在学号那一栏下面，不只是一闪而过的提示。改名保存后提示"已保存。学号 / 工号改成了 X，下次登录要用新的"（`renamedMessage`）；管理员改的是自己时，侧栏里的账号信息随即刷新。
- **个人信息**：`PATCH /api/auth/me/` 只认 `email`、`phone`、`research_direction`；姓名、登录名、角色在 `MeSerializer` 里只读，发了也忽略。未改初始密码时 403 `password_change_required`，和其他业务接口一致（`GET` 仍然放行）。
- **头像菜单**（`layouts/SideNav.vue`）：最上面一张不能点的账号卡片（大头像、姓名、"角色 · 课题组"、"学号 / 工号 xxx"），然后"个人信息""修改密码"，隔一条线"退出登录"。"个人信息"是 `FormDialog`（`sm`，`layouts/ProfileDialog.vue`）：姓名、学号 / 工号、角色、课题组写成文字，邮箱一整行，电话和研究方向两列；底下一行次要文字按角色说明找谁改其余几项（学生找课题组管理员，导师找运维，管理员在"成员"里自己那一行改）。
- DESIGN.md：账号菜单的内容；"能看到但这里不能改的项写成文字，不放灰掉的输入框"；409 用 `useFieldErrors(…, 'username')` 显示在字段下；用词表加"学号 / 工号，不说用户名"。

## Alternatives considered

- **只在 Django 后台改**（原状）：不用写代码。但要上服务器建隧道，管理员做不了，用户明确不要。
- **只允许运维改**：最稳，学号是登录凭据的一半。但学生填错学号这种事每学期都有，都要找运维太绕；管理员本来就能新建、停用、重置本组学生的密码，改登录名的权限不比这些大。
- **审核时在"待审核"表格里直接改学号**：改在源头。但要在审核表格里加编辑，通过以后发现的还是要另一个入口；编辑弹窗一处就够。
- **本人也能改自己的学号 / 姓名**：最省事。但姓名、学号是别人认人的依据（实验记录、审批、周报都按姓名显示），本人随便改容易冒充，也会让管理员核对过的学号失效。
- **飞书式的个性签名、状态、名片二维码、多账号切换**：对课题组工作没有用处，没做。
- **邮件提醒开关**：每天有提醒，填了邮箱就收，关不掉。要加字段和迁移，用户这次没有要求，没做。

## Consequences

- 管理员改名后，要自己告诉对方用新学号登录（平台不发通知：对方没登录时也看不到站内通知）。
- 学号格式只按 Django 默认规则（字母、数字和 `@.+-_`），不核对学校的学号格式。
- `/admin/` 里仍然能改登录名，和页面上改的是同一个字段。
- 验证：后端测试——管理员改学生学号后新号能登录、旧号不能，原样提交 200，被本组 / 外组 / 运维占用 409，含空格 400，外组账号 404，学生改自己 403；运维改名、409、400；本人改邮箱电话研究方向、改姓名登录名角色无效、邮箱格式 400、未改初始密码 403。三个测试在改动前的代码上都失败。前端测试：个人信息只提交三项并更新侧栏数据；改名提示。浏览器（验证实例，1440 宽）：`mgr` 头像菜单卡片、个人信息弹窗（错误邮箱提示在字段下，改对后保存关闭）；成员页把"新同学"改成 `s_a` 字段下提示占用、改成 `2026099` 成功、再改回 `s_new`；`ops` 在系统管理里同样改名、占用提示、改回。
