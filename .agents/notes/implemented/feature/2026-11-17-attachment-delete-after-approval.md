# Agent Note: 审批后上传的采购附件可以删除，已交财务的报销不能再传附件

Status: implemented

## Problem

[第三期笔记](./2026-11-17-phase3-procurement-and-reimbursement.md)定的规则是"附件只在草稿时能删"，但上传时不检查单据状态。对 `16c38ee` 的审计发现两者对不上：已到货的采购、已到账的报销都能上传附件（201），上传人和管理员却都删不掉（409）。传错的文件（例如误传了别人的证件扫描件）只能找运维进 `/admin/` 删除。

不能简单地禁止冻结后上传：采购发票常常在批准、到货之后才拿到。也不能什么时候都能删：待审期间，申请人可能在审批人点"通过"之前删掉报价单，而过期检查只比对状态和合计。2026-11-17 用户确认按本方案改。

## Decision

**采购申请**

- 上传：照旧，申请人和管理员在任何状态都能传。
- 删除（上传人或管理员）：
  - 草稿：可以删。
  - 待初审、待终审：409，提示"审批中的申请不能删除附件，请先撤回"。
  - 已批准、已采购、已到货：只能删最近一次审批之后上传的附件，也就是审批人没见过的；否则 409，提示"审批人已经看过这份附件，不能删除"。判断方法是这张单没有创建时间不早于附件上传时间的审批记录。
- 前端：`purchaseFileDeletable()`（`frontend/src/utils/format.ts`）按同样的规则决定是否显示"删除"按钮，服务器照样再检查一次。

**报销**

- 上传和删除都只限"待提交"。已交财务、已到账后上传返回 409，提示"已交财务的报销不能再上传附件；需要补充请管理员先退回“待提交”"。
- 上传时锁住这条报销再检查状态，和交财务用同一把行锁，所以不会在交财务的同时溜进一个附件。
- 前端：非"待提交"的报销不显示上传区。

## Alternatives considered

- **审计的原始建议：附件上传之后还没有人审批或交财务就可以删，包括待审期间**：改动最少；但待审期间还没有审批记录，申请人可以在审批人点"通过"之前删掉报价单。
- **冻结后一律不许上传**：规则最简单；但采购发票往往在批准、到货之后才有，没地方放。
- **允许管理员随时删除任何附件**：处理误传最省事；但审批时看过的报价单能被事后删掉，审批记录就对不上材料了。
- **保持现状，误传找运维**：不用改代码；但要进 `/admin/` 改数据，涉及隐私的误传文件处理不及时。

## Consequences

- 收益：采购批准后补传的发票、到货单传错了能自己删；审批人看过的材料删不掉；报销不再出现"能传不能删"。
- 测试：
  - 后端 `test_files_a_reviewer_has_seen_stay`：批准后补传的发票能删，审批前上传的报价单 409；到货后管理员补传的附件能删，报价单仍是 409。
  - 后端 `test_handed_in_reimbursements_take_no_more_files`：交财务、到账后上传都是 409，发票删不掉。
  - 两个测试在旧代码上都失败。前端 `utils.test.ts` 覆盖 `purchaseFileDeletable` 的四种情况。
- 浏览器（verify-lab，2026-11-17，代码 `c38b47a`）：
  - 草稿的报价单有"删除"按钮，提交后没有。
  - 两级审批通过后，学生补传一张发票，只有这张有"删除"，确认后删掉；报价单仍在。
  - 报销交财务后，对话框里没有"上传附件"，也没有"删除"。
  - 数据库读回：采购单只剩报价单，报销留着发票。
- 代价：报销交财务、到账后不能再补材料，要先找管理员退回"待提交"。
- 判断偏保守：依据是附件和审批记录的创建时间，两者都由服务器写入；采购上传不锁单，所以审批人点"通过"前一刻刚传上来、其实没看到的附件，也算看过，不能删。删除本身在这张单的行锁下检查。
