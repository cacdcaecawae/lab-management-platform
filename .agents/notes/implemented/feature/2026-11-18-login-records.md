# Agent Note: 最小化登录记录

Status: implemented

## Problem

系统现有登录时间只保留最后一次成功；实际认证失败和限流事件没有可查询的运维记录。

## Decision

- 成功/失败记录结构化结果、认证时刻、已知用户 FK 与来源 IP。仅匹配原本已存在的账号，不保留失败表单里的用户名文本、密码和 UA；删除用户后账号归属为空。筛选及榜单使用现行登录名。
- 认证与审计采用同一个地址规则：按部署配置取受信任 X-Forwarded-For 链末端的指定跳数，仅接受可解析 IP；链缺失、过短、格式不对或不启用代理模式时使用 socket 来源。链可信依赖后端不直通公网、受信任代理补写链及代理层数准确。
- 应用限流只记录全站每分钟一个「发生过」标记，无地址和账号；每进程每分钟最多申请一次，缓存标记与数据库唯一性跨进程去重。不保存请求数量，不改变 429，反代直接拒绝的请求不在统计里。安全校验挡掉的非认证请求不作认证结果。
- 运维只读分页、按账号与结果/时间筛选、已知账号认证失败近 24 小时前五；不会给组管理员。写入失败不影响认证结果，不把异常详情和表单内容打到诊断日志。
- API 仅展示近 180 天；独立幂等 `purge_login_events` 可按批物理清理过期行，有只读 dry-run。新采集默认关闭，部署方验证每日清理任务与失败监控后方可显式开启。本 PR 不启用生产调度或执行真实删除；备份/基础设施日志另有保留策略。

## Alternatives considered

- 逐请求保存 429、原样用户名、完整 UA：不必要地保留任意内容，也会把限流路径变成审计写入放大。
- 按账号/地址分桶统计 429：桶数受输入决定，不够有界。
- 概率清理或搭附提醒邮件：保留窗口不可预测，也引入无关功能依赖。

## Consequences

- PostgreSQL 测试验证认证结果、源地址、429 聚合去重、写入异常、分页/过滤/权限和恰好 180 天的清理边界。
- Vue 组件测试验证结构化结果展示与筛选。真实浏览器验收另列。
