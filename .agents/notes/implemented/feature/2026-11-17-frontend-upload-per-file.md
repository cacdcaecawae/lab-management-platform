# Agent Note: 前端逐个文件上传，浏览器不计算 SHA256（原 D20、D21）

Status: implemented

## 问题

用户一次可能选多个大文件（单个最大 2GB）。需要显示上传进度、处理同名冲突，并让用户能核对文件完整性。

## 决策

- 前端逐个文件上传，每个文件单独显示进度；一个文件冲突（409）不影响其他文件。
- 后端接口仍支持多文件原子上传（见 [文件上传与存储](../architecture/2026-11-16-file-upload-and-storage.md)）。
- SHA256 只在服务器入库时计算并展示，用户可以与本地值比对。

## 曾考虑的替代方案

- **一次请求上传全部文件**：接口支持，而且是原子的；但前端无法逐个显示进度，一个冲突会让整批失败。
- **浏览器端计算 SHA256 再与服务器比对**：可以自动校验；但 2GB 文件在浏览器内整体读入不现实。

## 后果

- 收益：大文件上传有进度，冲突只影响单个文件。
- 代价：前端的多文件上传不是原子的，可能部分成功；完整性需要用户自己比对。
