# Agent Note: 管理员只能管理学生账号和自己的资料（原 D24、D27）

Status: implemented

## 问题

组管理员可以新建成员、修改资料、重置密码。第一期审查 H1 发现：如果运维账号（超级用户 / staff）也在本组，管理员可以通过重置密码接管运维账号，进而访问所有课题组。同样，管理员如果能改导师账号或自建"导师"账号，就能冒用导师身份，绕过第三期采购的导师终审。

## 决策

- 成员接口的修改和重置密码只对本组学生账号和管理员本人有效；导师、管理员、超级用户、staff 账号都排除在外（`backend/accounts/member_views.py` 的 `get_queryset()`）。
- 新建或修改成员时，角色只能设为学生；管理员不能修改自己的角色（`backend/accounts/member_serializers.py` 的 `validate_role()`）。
- 导师和管理员账号由运维在 `/admin/` 管理。角色约定见 [角色与课题组隔离](../architecture/2026-11-16-roles-and-group-isolation.md)。

## 曾考虑的替代方案

- **只排除超级用户和 staff 账号（原 D24）**：能挡住接管运维账号；但管理员仍能修改导师账号或新建"导师"账号。已被本方案取代。

## 后果

- 收益：管理员无法冒用导师或运维身份。
- 代价：增加导师或管理员、修改他们的资料，都要找运维。
