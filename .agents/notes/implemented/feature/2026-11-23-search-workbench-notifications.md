# Agent Note: 全站搜索、工作台待办和站内通知补漏（issue #48 N6）

Status: implemented

## Problem

- 全站搜索（`workbench/search.py`）：
  - 找不到成员、经费来源、报销、任务和里程碑、组会行动项、数据集里的文件名。
  - 搜周报只按日期，结果不显示是谁的周报；搜组会只按标题，可每场都叫"组会"，结果分不出来。
  - 下拉结果不能用键盘 ↑ / ↓ / 回车选择。
- 工作台漏了几类待办：待审核的注册申请、已批准待采购和已采购待到货的申请（管理员）；自己的处理记录草稿、采购草稿；缺发票的报销；逾期的项目任务汇总。"未交周报"和"全部 N 条"的链接没带上筛选或标签，点过去还要再选一次。
- 站内通知漏了：任务指派给你、你被排为组会主讲人、学生提交了周报（给导师）、报销到账或被退回（给报销人）、管理员取消了你的预约、耗材跌破安全库存（给管理员）。
- 快到期的耗材批次没进每日提醒邮件。通知中心不能按模块筛选，也不能单独把一条标为已读。
- R1 之后，学生 + 管理员的工作台有了"supervisor"那一块（采购待审），"写本周周报"的提醒却是按"没有那一块"判断的，于是他们不再被提醒。
- 相关决定：[全站搜索](./2026-11-18-global-search.md)、[通知中心](./2026-11-18-notification-center.md)、[工作台提醒](./2026-11-18-workbench-reminders.md)、[每日提醒邮件](./2026-11-18-scheduled-reminder-mail.md)、[列表筛选与编号搜索](./2026-11-23-list-filters-sorting-and-suggestions.md)。

## Decision

- **搜索**：
  - 新增七类，数据范围与各自的列表一致：成员（本组；导师、管理员还按学号）、经费来源（本组）、报销（`scope_finance`）、任务和里程碑（本组项目，链接到项目的对应标签）、行动项（本组，链接到组会）、数据文件（`scope_private`，链接到所在数据集）。
  - 链接模板可以引用这一行选出的字段（如 `{project_id}`），不再只能用 `{id}`。
  - 周报按学生姓名也能搜到，副标题是姓名；组会搜纪要和议程，副标题是日期。副标题一律转成文字。
  - 搜一个完整编号时，按 `core.filters.code_lookup` 精确命中（与列表搜索同一个规则）。
  - 搜索面板的输入框是 combobox、结果是 listbox：↑ / ↓ 移动，回车打开，Esc 关闭。
- **工作台**（`/api/dashboard/`）：
  - `my`：处理记录草稿、从没提交过的采购草稿、待提交且没有发票的报销。
  - `manager`：待审核注册、已批准待采购、已采购待到货。
  - 顶层 `overdue_tasks`（导师、管理员）：本组项目里截止日期已过、未完成的任务数，右栏显示，链到项目列表。
  - 链接带上筛选：未交周报 → 那一周的未交名单（`?tab=missing&week=`），待反馈 → `?tab=pending`，周报需补充、实验 / 处理记录未提交、采购草稿、待采购、待到货、缺发票的报销 → 各列表带状态（列表页从地址读 `status`、`owner`、`mine`），我的行动项 → 组会的"行动项"标签带负责人，待登记使用 → 预约列表的"待登记"。
  - "写本周周报"改为按基础角色是学生判断（R1 的遗漏）。
- **通知**：都在已有的状态变化处调用 `notify()`，和变化在同一个事务里：
  - 任务指派（新负责人；自己接的不发，改别的字段不重复发）。
  - 排进组会议程的汇报人（新加进来的；自己排自己不发）。
  - 学生提交周报（本组导师，`role="advisor"`）。
  - 报销被别人标为到账或退回待提交（报销人）。
  - 管理员取消预约（预约人）。
  - 耗材一次领用或调整使库存从安全库存以上跌到以下（管理员）；还在线下时不再发，补货回到线上后再跌破才再发。只看"这一笔跨过了线"，不用另记状态。
  - 每日提醒邮件给管理员的那一份加"耗材批次到期"：还有库存、在当天、7 天后、30 天后到期的批次（和设备校准提醒同样的几天，避免天天重复）。
- **通知中心**：`?module=` 按链接前缀分到侧栏的几组（项目、科研记录、周报组会、设备耗材、采购经费、成员），不改表；每条未读的加"标为已读"。点开一条照旧会标已读。
- 不做工作台的"经费概况"：用户决定不要预算（N1）。

## Alternatives considered

- **全站搜索改用 PostgreSQL 全文检索**：大数据量时更快；但中文分词要装扩展，知识库搜索已经选了子串匹配。保持一致，数据多了再加 `pg_trgm` 索引。
- **通知的模块存成一列**：筛选更直接；但通知已经存了链接，模块从链接前缀推得出，不用迁移旧数据。
- **低库存每次领用后都通知**：不会漏；但一个耗材连续领几次就会刷屏，所以只在跨过安全库存那一笔发。
- **耗材到期每天都写进邮件**：不会漏看；但一批货 30 天里会出现 30 次。沿用校准提醒的三个时间点。
- **通知链接带上 `?item=`、`?booking=` 这类参数**：能直接打开那一条；但通知的链接只允许站内路径（防止写进任意地址），报销、预约的通知链到列表页，正文写明是哪一条。

## Consequences

- 测试：
  - `workbench/tests/test_search.py`：新的七类、编号命中、学号只给导师和管理员、外组隔离；每次搜索的查询数上限从 15 改为 25（每类一条查询）。
  - `workbench/tests/test_notices_and_todos.py`：六种新通知谁收到、谁不收到（低库存只在跨线时发、被拒的领用不发）；工作台的新待办；通知中心按模块筛选；每日邮件里的批次。
  - 前端：`SiteSearch.test.ts` 键盘选择；`WorkbenchView.test.ts` 学生 + 管理员的周报提醒和新链接。
- 搜索每多一类就多一条查询，二十类仍在一个请求里；数据多了按需加索引。
- 通知变多以后容易被忽略：每种都只发给必须处理的人。
- verify-lab 的 `search.md`、`notifications.md` 已更新（工作台的新待办也写在 `notifications.md`）。
