# Agent Note: 耗材批次与有效期

Status: implemented

## Problem

开发手册把"耗材批次与有效期"列为暂不做。超声检测用的耦合剂、清洗剂、部分胶粘剂有保质期：过期的耦合剂会影响声耦合，数据不可靠。现在耗材只有总库存（由流水汇总），不知道库里哪一批什么时候过期，也没法做到先用快过期的。

需要用户确认的点：哪些耗材要按批次管。默认做成每个耗材单独开关，不开的保持现状。

## Decision

**模型**（`inventory` app）：

```
Consumable.tracks_batches  Bool，默认 False
Batch(consumable → Consumable PROTECT, batch_no ≤50, expires_on Date null, created_at)
    唯一约束：(consumable, batch_no)
StockTxn.batch → Batch null PROTECT
```

**规则**（只对 `tracks_batches=True` 的耗材生效）：

- **入库**：必须填批号，有效期可填；批号不存在就新建批次，存在就加到那一批上。
- **领用、退回、盘点调整**：必须选批次；每个批次的库存（该批流水之和）不能小于 0，超出就 400，提示"该批次库存不足：当前 N"。
- **耗材总库存**：仍然是全部流水之和，继续使用现有的盘点版本校验（`stock_version_seen`）；模式切换写零数量标记以拒绝旧盘点（包括开关 ABA）。
- **打开开关**：只有当前库存为 0 时才能打开，否则 409，提示先盘点清零，或者在同一个请求里带上"期初批次"（批号、有效期），在同一事务中成对记未分配减少与期初批次增加，总库存不变。
- **关闭开关**：只有每个批次的库存都为 0 时才能关闭。
- **建议领用的批次**：接口返回各批次的库存，按有效期升序（无有效期的排最后）；前端默认选第一个有库存且未过期的，可以改；有效期当天允许领用，过期后不能领用，退回或管理员纠正仍可用。

**接口**：

- `Consumable` 新增 `tracks_batches`，以及 `batches: [{id, batch_no, expires_on, stock}]`（含零库存，允许选择原批次退回）、`nearest_expiry`。
- `StockTxn` 新增 `batch_no`（入库）或 `batch_id`（其他类型）。
- 列表新增筛选 `expiring_within=<天数>`。

**前端**：

- 耗材表格新增"最近到期"一列，30 天内到期标橙、已过期标红。
- 入库对话框在开关打开时多出"批号""有效期"；领用、退回、盘点对话框多出"批次"下拉框，显示各批次的库存和有效期。
- 管理员工作台新增"30 天内过期的批次"。2026-11-21 起也列出已经过期、仍有库存的批次（排在最前，标红，写"已过期"）：过期的耦合剂还在柜子里，比快过期的更需要处理；列表的 `expiring_within` 同样包含它们，筛选胶囊改叫"30 天内到期（含已过期）"，和设备的"校准到期（含已过期）"一致。

采用独立管理员模式接口，切换要求已看到的库存版本。历史流水不回填，不自动为任何真实耗材开启；迁移后须确保所有写入端均运行新版，再启用选定耗材。

## Alternatives considered

- **每次领用自动扣最早到期的批次（先到期先出）**：省一步操作。但实际拿的未必是最早那一批，账就和实物对不上了；所以默认选中最早的，让人确认。
- **所有耗材都按批次管**：规则统一。但线缆、探头楔块这类东西没有有效期，强制填批号只会制造麻烦。
- **只给耗材加一个"有效期"字段**：最简单。但同一种耗材常常有几批不同的有效期，一个字段表达不了。

## Verification

- 后端测试：
  - 开关开着时，入库没批号、领用没批次都返回 400；
  - 批次库存不能为负；
  - 开关的两个条件；
  - 期初批次；
  - 盘点版本校验仍然有效（复用 `test_stocktake_version.py` 的场景加上批次）；
  - 没开开关的耗材，行为和现在完全一样（现有测试原样通过）；
  - 外组隔离。
- 前端测试：领用对话框默认选中最早到期且有库存的批次。
- 浏览器：管理员打开开关、入两批不同有效期的耦合剂；学生领用时默认选中早到期的那一批；管理员工作台出现即将过期的批次。更新 `features/consumables.md`。

## Risks

- 加锁：现有的入库和领用锁住耗材这一行再计算库存。批次库存的计算要在同一把锁下进行，不能另开查询，否则两个人同时领同一批会超领。
- 迁移：`StockTxn.batch` 可为空，不需要回填历史数据。

## Consequences

- 按批次管理默认关闭，不自动选择或启用任何真实库存。模式变更和每笔流水锁定同一耗材行；期初转拨净额为零，开关标记参与现有版本检查。批号的有效期不能被重复入库覆盖。
- 新列保留数据库默认值，旧进程即便插入未带新列的无批次耗材仍得到关闭状态；发布时先应用迁移，再切换所有库存写入端，最后由管理员选择开启。启用后不得混跑旧写入端。没有批次使用历史时可以逆迁移；存在模式标记、批次或分配记录时，反向迁移在改变任何数据库结构之前拒绝，不应删除记录强行回退。
- PostgreSQL 回归覆盖总量守恒、事务回滚、ABA、外组、过期边界、历史零库存退回、期初迁移兼容、两连接并发领用。Vue 组件回归验证默认选最先到期的可用批次。
- 隔离 PostgreSQL、Django、Vite 启动成功；环境拒绝 Chromium 本地 socket，未完成浏览器流程，不写成通过。
