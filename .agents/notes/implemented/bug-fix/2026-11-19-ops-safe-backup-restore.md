# Agent Note: 备份仓库、换库和更新的停站边界

Status: implemented

## Problem

此前的备份读不到仓库时会尝试初始化，NAS 掉线可能在宿主磁盘上另起仓库；更新停站前未核对仓库和版本方向。恢复的两次换名不在同一事务，第二次失败会让服务找不到原库。

## Decision

常规备份、恢复、升级或演练在使用本地目录前核对路径，NAS 可配置强制精确挂载点。常规流程不初始化仓库；初始化需明确指定，只在已存在的空目录进行。更新只接受有 Git 祖先关系的较新正式版本，停站前检查仓库和数据库迁移记录；自动回退使用本次冻结的快照，不走手工降级逻辑。换库在同一 PostgreSQL 事务中完成，连接已断等不确定结果时不盲启服务。

## Alternatives considered

没有在备份失败后尝试新建仓库；没有将两次换名拆成需要补偿的两个提交。

## Consequences

不会验证用户真实 NAS 或生产数据；挂载须由部署侧保障稳定，外部维护动作不得并发执行。
