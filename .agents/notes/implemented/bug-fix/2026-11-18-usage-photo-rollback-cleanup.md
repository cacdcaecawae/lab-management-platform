# Agent Note: 使用登记事务失败时清理本次新照片（issue #3）

Status: implemented

## Problem

设备使用登记保存照片后，设备更新或数据库事务失败会回滚数据库，但照片仍留在持久化卷。issue #3 已用隔离环境复现：记录 0 行、照片 1 个。

## Decision

2026-11-18 用户授权对确定问题自主稳妥修复，但只能先提 PR；本方案据此作小范围实现，不合并、不部署。

- 保留本次新建的 UsageReport 实例，使插入失败时也能定位已写入的照片。
- 整个事务失败时仅清理该实例新上传的照片；清理失败记日志并保留原异常。
- 事务提交后先标记成功，再执行现有通知，避免提交后异常误删已保存的照片。
- 不改变预约锁、设备锁、状态机、权限或接口契约，不清理任何其他请求的文件。

## Alternatives considered

- 定时扫描孤儿文件：范围较大，误删风险高，不适合本次修复。
- 只在 body.save 成功后记录文件：覆盖不到数据库插入失败时已写入的照片。

## Consequences

新增插入失败、后续失败、清理失败、成功与提交后异常测试。TLA+、浏览器及 PostgreSQL 的实测范围在交付前记录。进程被强制终止或存储无法删除时仍可能留下文件，本修复不声称分布式事务原子性。

## Validation

- 独立 SQLite 内存库、临时 MEDIA_ROOT，直接运行实际 report 视图、序列化器、FileField 及事务，模拟 booking 查询和 equipment 更新。五条故障/成功路径通过：INSERT 后失败、设备更新失败、清理失败仍保留原异常、提交后通知失败不删照片、成功及重复登记不删旧照片。
- 同一隔离复现脚本在未修复版本的第一条路径失败（数据库 0 行仍有 1 个照片），修复后 0 行且无照片。
- 新增正式 PostgreSQL API 回归测试 5 个用例（包括成功后重复登记）；当前无可用 PostgreSQL 服务，未运行这些 API 测试或完整后端回归。SQLite 结果不能替代 PostgreSQL 锁和事务行为验收。
- Python 编译检查通过。TLA 检查脚本已尝试，缺少 tla2tools.jar，未运行 TLC。锁顺序、事务内状态转换、预约规则均未改变；新文件清理和提交回调不在现有 TLA 模型中。不更新 SYNC 冒充模型已验证。
- 真实浏览器隔离栈未启动，没有浏览器验收证据。合并前仍需 PostgreSQL 回归、TLC 与设备上传/下载浏览器检查。

- 独立只读审阅未发现阻塞草稿 PR 的问题。补偿仅覆盖当前 endpoint 的事务边界；将来若新增 ATOMIC_REQUESTS 或外层事务，方法返回后才发生的外层回滚仍可能留下孤儿文件，必须重新设计补偿。
