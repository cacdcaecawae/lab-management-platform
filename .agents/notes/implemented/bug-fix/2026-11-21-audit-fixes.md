# Agent Note: 全项目审计的修复：更新前快照不被清理、后台只在本机端口、磁盘余量拦截上传

Status: implemented

## Problem

2026-11-21 对 `main`（`c22694e`，v0.1.1）做了一次全项目审计（Fable，只读）。组间、学生间的隔离没有找到漏洞，下面这些要修，用户同日确认了修法：

- **更新前的快照当晚就被删**（P1）：`backup.sh` 的清理是 `forget --keep-daily 30 --keep-monthly 12`，每天只留最后一份，不看标签。白天 `update.sh` 做的 `before-<版本>` 快照，当晚 2:30 的每日备份一清理就没了；备份容器按 UTC 算天，北京时间 8:00 到次日 2:30 的更新都和当晚备份算同一天。更新失败、迁移已改时，脚本让运维用的正是这份快照。审计用真实 restic 0.19.1 复现：`remove 1 snapshots: before-v0.1.2`。
- **`/admin/` 对公网开放**（P2）：运维在业务接口里没有特殊权限，但后台能看、改、删所有课题组的数据，包括已提交锁定的实验记录；后台登录只有 Nginx 按 IP 每分钟 60 次，用户名固定是 `ops`；一键安装打印的一次性密码不改也能进后台（改密码的强制只在业务接口）。
- **磁盘写满前没有拦截**（P2）：默认安装里数据库、上传文件、上传暂存和备份都在系统盘，任何成员都能反复上传 2 GB 文件；盘满后 PostgreSQL 写不进去，整站停摆，当晚备份也失败。"存储"页只显示数字，不提醒。
- 小问题：容器日志不限大小；`update.sh` 没处理 SSH 断线（HUP）；两人同时给同一条成果上传全文会留下没人引用的文件；登录的按账号限速计数不是原子的。

## Decision

- **备份保留**：清理改为 `forget --keep-within 14d --keep-daily 30 --keep-monthly 12 --prune`，最近 14 天的快照全留，包括更新前和手动做的。取代[发版、更新与备份](../process/2026-11-18-release-update-backup.md)里的清理规则。
- **后台只在本机端口**：
  - 对外的 80/443 上 `/admin/` 返回 404。后台和它的静态文件改由 Nginx 的另一个 server（`listen 8081`，`infra/nginx.admin.inc`）提供，HTTP 配置和 HTTPS 模板里都有；Compose 只把它发布在宿主机的 `127.0.0.1:${ADMIN_PORT:-8091}`。运维在服务器上打开，或用 `ssh -L 8091:127.0.0.1:8091` 隧道。后台登录仍保留 Nginx 的限速。
  - 这个端口转给 Django 的 Host 带端口（`$http_host`），Django 按浏览器的 Origin 核对 CSRF；`ALLOWED_HOSTS` 总是加上 `localhost`、`127.0.0.1`。
  - 后台也要求先改初始密码：`admin.site.has_permission` 在 `must_change_password` 时返回假，登录后回到登录页。
- **磁盘余量**：`core.disk.DiskSpaceGuard` 排在上传处理器第一位，在接收文件之前比较"上传暂存目录和附件目录所在磁盘中较小的剩余空间"减去请求体大小，低于 `MIN_FREE_DISK`（10 GB）就返回 507 `insufficient_storage`"服务器磁盘剩余空间不足，暂时不能上传，请联系运维"。所有上传接口一样。`/api/system/storage-status/` 增加 `disk_free`、`disk_low`，余量不足计入 `attention`，"存储与备份"页显示剩余空间和"不足，已暂停上传"。
- **小问题**：
  - Compose 给 db、backend、web 设 `json-file` 日志，每个容器最多 5 个 10 MB 文件。
  - `update.sh` 在新版本开始启动前收到 HUP 时和 INT、TERM 一样以 129 退出并恢复原站；通过 SSH 且不在 tmux / screen 里运行时，开头提示一次。README 写明要在 tmux / screen 里运行。
  - 成果全文上传和删除在事务里先 `select_for_update` 锁住这条成果，再读旧文件名。
  - 登录限速的非原子计数接受现状，在接口文档里写明硬上限是 Nginx 按 IP 每分钟 60 次。

## Alternatives considered

- **只清理带 `daily` 标签的快照（`--tag daily`）**：更新前和手动快照永远不清理，会一直累积；`--keep-within` 两周后照常清理。
- **`--keep-tag` 保留更新前快照**：标签带版本号（`before-v0.1.2`），要再加一个固定标签；同样永不清理。
- **在主端口按来源地址放行后台**（Nginx `allow 127.0.0.1` 加私有网段）：不用新端口。但宿主机本机连接经过 Docker 后显示为网桥地址，只能放行整个私有网段；云服务器前面若有负载均衡或代理，所有外部请求都会变成私有地址，后台就对所有人开放了。单独的回环端口只在宿主机上可达，配错了也只是打不开。
- **只把后台登录收紧到每分钟 5 次**：改动最小，但后台仍在公网上，暴露面不变。
- **去掉 `/admin/`**：最彻底，但删数据集等少见操作没有替代页面。
- **只在视图里、文件存好之后检查空间**：文件已经写进暂存目录，盘真满时暂存这一步就会失败成 500；放在上传处理器里，在接收文件之前就拒绝。
- **按用户或课题组的存储配额**：能防单个人占满，但要定配额、加管理界面；先用全局余量兜住"整站停摆"。

## Consequences

- 旧版本（v0.1.1 及以前）的更新前快照不受新规则保护，直到第一次用新脚本备份。
- 每次备份会多留最多 14 天的快照，restic 去重，增加的空间很少。
- 运维进后台要先建 SSH 隧道；本机试用（`trial.ps1`）直接打开 `http://localhost:8091/admin/`。同一台机器上两套部署要给 `ADMIN_PORT` 设不同的值。
- HTTPS 部署下，Django 也接受 Host 为 `localhost` / `127.0.0.1` 的请求（对外 443 上也一样）；站内链接用的是 `SITE_URL`，不受 Host 影响。
- 后台的上传（Django admin 不走 DRF）在磁盘不足时是 500，不是 507。
- 余量阈值写死 10 GB；数据盘很大时也可能过早或过晚，以后有需要再做成配置。
- 磁盘余量只在上传时检查，数据库本身的增长、日志、备份仓库占满不会被拦，只会在"存储与备份"显示"需处理"。
- 验证：
  - 备份保留用真实 restic 0.19.1 演练：旧规则删掉 `before-v0.1.2`，新规则 3 份全留（within 14d）。
  - 用这次改动构建的镜像起一套一次性环境：对外端口 `/admin/`、`/admin/login/` 是 404；后台端口只发布在 `127.0.0.1`，登录页和后台 CSS 是 200，带 Origin 的登录通过 CSRF；未改初始密码时登录后 `/admin/` 回到登录页，改后 200；三个容器的日志都是 `json-file` 10 MB × 5。
  - HTTPS 模板用自签证书 `nginx -t` 通过。
  - 507、`disk_low` 和页面上的"不足，已暂停上传"由自动化测试覆盖；新加的测试在旧代码上失败。
