# Agent Note: 合并待办功能时统一运维目标与页面状态

Status: implemented

## Problem

恢复演练、本地备份和应急启动可能使用不同的仓库或 Compose 覆盖。NAS 身份失配时容量页仍读取错误磁盘。运维账号看到必然返回 403 的搜索入口，工作台链接的筛选在同页跳转后残留。

## Decision

- 运维命令复用实际部署的 Compose 项目和文件列表；演练从配置文件取得备份仓库和密码。NAS 身份失配时容量不可用。更新先完成静态 HTTPS 目标检查，再调用 Compose。
- 搜索入口与接口使用同一账号范围。试件和设备列表响应链接筛选变化。公共工作台使用项目模块允许的查询和序列化器入口。
- 保留各分支的功能和原提交；在合并候选上检查模型、迁移、浏览器、依赖边界以及脚本和前后端测试。

## Alternatives considered

逐个接受绿色 PR 无法发现不同分支单独改动同一页面、路径和运维参数后的错误。为旧前端目录保留重复入口会使模块依赖检查失效。

## Consequences

演练固定仓库配置，身份不符的 NAS 不显示容量；组合配置不得丢失 HTTPS 或 NAS。清除导航筛选后列表重新查询，运维账号无法打开全站搜索。本地完整检查通过（后端 450 通过、1 个 POSIX 包装用例跳过，Linux 单独运行脚本 47 项通过；前端 121 项、类型检查和构建通过）。设备模型 10 个场景符合预期，独立浏览器用三种角色走通 12 条页面路径。真实 Nginx 回 204 后健康检查必须关闭输入管道，避免 Compose 等到超时导致误报。

## 恢复范围

隔离测试使用合成数据。真实 NAS 挂载、证书签发和生产备份依赖现场配置。

新版 web 在健康检查期间已经发布端口，用户可能成功写入。若此时检查失败且迁移发生变化，自动恢复旧快照会覆盖窗口内的写入。脚本立即停站，保留当前数据库和上传文件，打印原版本、目标版本、快照编号和人工恢复步骤；迁移未变时仍可自动退回。恢复自动化若要保留到跨迁移回退，需要独立的不对外验收阶段。
