# Agent Note: 三种角色，按课题组隔离，运维不获得业务权限（原 D6、D8）

Status: implemented

## 问题

会议定的是"管理员看全部，学生看自己"，并计划推广到其他课题组。需要确定角色集合、运维账号的权限，以及第一期是否就支持多个课题组。

## 决策

- `User.role` 只有 student 学生、manager 管理员、advisor 导师；管理员和导师合称 supervisor，只能看本组数据。
- 运维用 Django 超级用户登录 `/admin/`，在业务接口里没有特殊权限。
- 第一期就有 `ResearchGroup`：成员和项目带课题组；个人数据通过 `owner__group_id` 归组，不在每张表冗余 group 字段。
- 数据范围的具体规则见 [数据范围与 404](./2026-11-16-access-scope-404.md)。

## 曾考虑的替代方案

- **运维账号自动获得业务数据访问**：方便排查问题，但运维不应自动看到科研数据。
- **推广到其他课题组时再加课题组**：第一期更简单；但会议已经计划推广，所以第一期就加。

## 后果

- 2026-11-23 起角色改为基础角色（学生 / 导师）加"管理员""终审人"两个标签，见[角色拆分](./2026-11-23-roles-and-identity.md)；下面说的三种角色和 supervisor 是之前的做法。
- 收益：外组管理员访问本组数据同样返回 404，各模块都有对应测试。
- 代价：`User.group` 是外键，一个成员只能属于一个课题组。
