# Agent Note: 角色拆成"导师 / 学生"加"管理员""终审人"两个标签，身份和词条只用于展示和筛选（issue #48 R1、S1）

Status: implemented

## Problem

- 原来 `User.role` 三选一：学生、管理员、导师。管理员和导师合称 supervisor，`scope_private()` 让他们看全组的实验记录、处理记录、数据集、周报、采购和报销。规则来自[角色与课题组隔离](./2026-11-16-roles-and-group-isolation.md)和[管理员只能管理学生账号](../feature/2026-11-17-manager-scope.md)。
- 课题组的实际分工不是这样。管理员可能是博士生、科研助理，也可能是导师本人；"管事务"和"看全组科研数据"是两回事：
  - 博士生当管理员时，能看到所有同学的实验记录和周报。
  - 导师兼管理员时，只能二选一。
- 采购终审是组里任何一位导师。一个组有几位导师（硕导）时，不是每位都管经费。
- 成员页只有姓名、学号、角色、研究方向：
  - 没有身份、年级、在籍或毕业。
  - 不能筛选，也不能导出花名册。
  - "教授""博导"这类称呼没有地方写；写进角色就成了权限。

## Decision

### 数据

- 基础角色 `User.role` 只有 `student` 学生、`advisor` 导师。
- 两个可叠加的标签：`is_manager` 管理员、`is_approver` 终审人。
- 成员资料只用于展示和筛选，不参与权限：
  - `identity` 身份（教师、博士后、博士生、硕士生、本科生、科研助理）。
  - `enrollment_year` 入学年份（页面写"2024级"）。
  - `graduated` 已毕业。
  - `tags` 词条，本组自由填写，最多 10 个、每个 20 字。
- 迁移 `accounts/0006`：
  - 原管理员迁成"学生 + 管理员"（用户选的推荐项）。
  - 原导师迁成"导师 + 终审人"，保持原来任何导师都能终审。
  - 可反向迁移。
- 在籍状态（`member_status`）由 `is_active` 和 `graduated` 合成：在籍、已毕业、已停用。
  - 只有在籍能登录。"已毕业"和"已停用"都不能登录（用户选的推荐项），只是写法不同。
  - 重新启用时清掉"已毕业"。

### 权限（`backend/core/permissions.py`）

| 能力 | 谁有 | 实现 |
|---|---|---|
| 看全组的实验记录、处理记录、数据集、周报；退回实验记录；批阅周报；未交名单；周报汇总和导出 | 导师 | `scope_private()`、`IsAdvisor` |
| 看全组的采购和报销；报销统计和导出 | 管理员、终审人 | `scope_finance()`、`IsFinance` |
| 采购初审；报销退回、到账；财务邮箱和提醒；台账、经费来源、组会、注册审核、新建学生 | 管理员 | `is_manager()`、`IsManager` |
| 采购终审；在成员页开关本组账号的"管理员" | 终审人 | `is_approver()`、`IsApprover` |
| 新建项目、换负责人、看盲测的缺陷参数、设备使用统计、本组存储用量、成员联系方式、花名册 | 导师或管理员 | `is_supervisor()`、`IsSupervisor` |

- 采购流程（`procurement/views.py`）：
  - 学生提交后，管理员初审，终审人终审。
  - 管理员自己的申请跳过初审。
  - 终审人自己的申请先由管理员初审，再由另一位终审人终审；组里没有别的终审人时，初审通过就批准。
  - 唯一的终审人又是管理员时，他自己的申请不跳过初审，避免没人能终审。
  - 组里没有任何终审人时，单子停在"待终审"（同原来没有导师时）。
- 同一张单的初审和终审：
  - 组里有另一位终审人时，做过初审的人不能终审，返回 403。
  - 组里只有他一位终审人时允许（用户选的推荐项），审批记录终审那一条写"初审和终审为同一人"（页面按两条审批的审批人推出，不另存字段）。
- 成员接口：
  - 管理员只能改没有标签的学生和自己，`role` 和两个标签只读。
  - 终审人用 `POST /api/members/{id}/manager/` 开关管理员标签，运维账号 404。
  - 基础角色和终审人标签只由运维在"系统管理 → 账号"里改。
- 通知按角色或标签发，`core.notifications.AUDIENCES`：
  - 注册申请、设备异常：发给管理员。
  - 待终审：发给终审人。
  - `User.audiences` 决定一个人读得到哪些，去掉标签以后，它带来的通知也看不到了。
- 每日提醒里给管理员的那一份按标签发。"周报未交"只发给基础角色是学生的人，学生 + 管理员也要交周报。

### 页面

- 前端 `auth` store：
  - 原来的 `isSupervisor` 拆成 `isAdvisor`、`isManager`、`isApprover`、`isFinance`、`isSupervisor`。
  - 原来用 `isSupervisor` 的每一处，按上表换成对应的能力。
  - 路由和菜单加 `meta.finance`："我的审批"给管理员和终审人。
- 成员页：
  - 列：角色（"学生 · 管理员"）、身份、年级、词条、状态。
  - 筛选：状态（默认在籍）、身份、角色、权限、年级、词条。
  - 导出花名册（导师、管理员）。
  - 编辑框加身份、入学年份、状态、词条。
  - 终审人每行有"设为管理员 / 取消管理员"。
- 系统管理 → 账号：基础角色、两个标签、身份、入学年份、词条。

## Alternatives considered

- **保留三选一的 role，再加一个"兼任管理员"**：改动最小；但"管理员看全组科研数据"仍绑在角色上，博士生当管理员看到同学周报的问题解决不了。
- **通用权限组（Django Group / 自定义权限表）**：最灵活；但只有两个标签，表结构和页面会复杂很多，导师和运维也难看懂谁能做什么。
- **身份直接决定权限（教师 = 导师）**：少一个字段；但硕导、博士后、科研助理的权限因组而异，issue 已经确认身份不绑权限。
- **单独存一列在籍状态**：读起来直接；但 `is_active` 已经决定能不能登录，两列要同步。改为加一个"已毕业"布尔，状态由两者合成。
- **审批记录里存一列"同一人"**：查询更直接；但两条审批的审批人已经说明了这件事，不必再存一份。

## Consequences

- 原管理员看不到别的同学的实验记录、数据集和周报了，周报未交名单和提醒里会出现他。
  - 如果他其实是老师或不写周报的科研助理，运维在"系统管理 → 账号"里把基础角色改成导师即可。
  - 发版说明里要写清楚。
- 测试：
  - 后端各模块的隔离测试按新标签改写：研究记录由导师看和退回，"学生 + 管理员"看不到别人的、调不了批阅接口。
  - 新增 `accounts/tests/test_roles_and_identity.py`：迁移、终审人开关管理员、资料和状态、筛选、花名册。
  - 新增 `procurement/tests/test_reviewers.py`：终审只到终审人、同一人两审的规则、终审人自己的申请。
  - 新增 `core/tests/test_scoping.py::test_scope_finance`。
  - 前端新增 `MembersView.test.ts`。
- verify-lab 的种子改为 `mgr` = 学生 + 管理员、`adv` = 导师 + 终审人。
- 旧笔记的决定由这篇取代：[角色与课题组隔离](./2026-11-16-roles-and-group-isolation.md)、[管理员只能管理学生账号](../feature/2026-11-17-manager-scope.md)。
