# Agent Note: 修改历史用 simple-history，多对多不进快照，变更原因存长文本（原 D17、D18）

Status: implemented

## 问题

实验记录、处理记录、周报需要修改历史（第一期验收标准 5：每次修改有历史记录），导师退回时要写原因。

## 决策

- 用 `django-simple-history` 记录每次保存的字段快照和操作者（`HistoryRequestMiddleware` 自动取当前用户）。
- 多对多关联（如实验关联的数据集）的变化不进入历史快照，这是库的默认行为。
- 历史记录的变更原因存为 TextField（2026-11-17 加入）。

## 曾考虑的替代方案

- **用 `m2m_fields` 记录多对多变化**：历史更完整；但关联变化本身可以从当前状态看到，提交后又会锁定，需要时再加。
- **simple-history 默认的变更原因字段**：最长 100 字，退回原因可能超过。这个问题由周报子代理在开发中提出。

## 后果

- 收益：字段级修改历史和操作者来自成熟库，不用自己写。
- 代价与重访信号：草稿阶段关联的增删没有历史记录；需要追溯这类变化时加 `m2m_fields`。
