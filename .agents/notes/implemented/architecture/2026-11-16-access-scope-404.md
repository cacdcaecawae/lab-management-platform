# Agent Note: 数据范围统一在查询集过滤，越权返回 404（原 D5、D7）

Status: implemented

## 问题

会议定的是"管理员看全部，学生看自己"。实验记录、数据集、处理记录、周报都是个人数据，必须防止学生用编号或下载链接读到别人的数据，也不能泄露别人的记录是否存在。开发手册待确认事项 3 还留了一个问题：同一项目的同学之间能否互看个人数据。

## 决策

- 所有业务视图的 `get_queryset()` 用 `core.permissions.scope_private()`（个人数据：本人 + 本组 supervisor）或 `scope_group()`（组内公开数据）构造。
- 越权访问返回 404 而不是 403：对象不在查询集里，自然得到 404。
- 同一项目的学生之间也不能互看个人数据。
- 引用其他对象时（实验关联数据集、周报关联实验等），被引用对象也要在同一范围内校验，不能只信任前端传来的 id。

## 曾考虑的替代方案

- **返回 403**：语义更直白，但会告诉请求者这条记录存在。
- **同项目同学可以互看个人数据**：便于协作；最终采用待确认事项 3 的默认值，遵循会议结论，不能互看。

## 后果

- 收益：权限规则集中在 `core.permissions`；每个资源都有"学生 A 用 B 的 id 读/写/下载 → 404"的测试（`docs/agent-tasks.md` 共同规则 4、5）。
- 代价：前端无法区分"没有权限"和"不存在"。
