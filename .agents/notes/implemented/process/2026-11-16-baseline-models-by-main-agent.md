# Agent Note: 第一期全部模型和 0001 迁移由主代理在基线中定义（原 D3）

Status: implemented

## 问题

第一期由 5 个子代理在各自的 worktree 并行开发。实验、处理记录、周报互相引用；如果每个子代理各自定义模型，会互相等待或重复定义，迁移也难合并。

## 决策

- 主代理在 M0 基线中定义第一期全部模型，并生成各 app 的 0001 迁移。
- 子代理只写序列化器、视图、`urls.py`、业务校验和测试。确需改模型时，只改自己 app 的 `models.py`，只生成本 app 的新迁移，并在交付说明里写原因。
- 合并后主代理执行 `makemigrations --check --dry-run`（已写入 `scripts/check.sh`）。

## 曾考虑的替代方案

- **各子代理定义自己 app 的模型**：分工更独立；但模型互相引用，会互相等待或重复定义，迁移也难合并。

## 后果

- 收益：子代理开工时模型已经齐全，不用等待彼此。
- 代价：模型问题要通过交付说明交给主代理改。例：周报子代理提出 history reason 的 100 字限制，由主代理改为 TextField（见 [修改历史](../architecture/2026-11-16-change-history.md)）。
