# Agent Note: 正式域名的 HTTPS

Status: implemented

## Problem

默认 HTTP 只适合校内网或 VPN。正式对外部署需要 TLS，不能让运维脚本把 HTTP 跳转误判成 Django 健康，或为启动 ACME 提前公开 HTTP 登录。

## Decision

- 基础 Compose 和试用配置仍然只用 HTTP。使用两个可选覆盖文件：引导阶段只提供 ACME HTTP-01 挑战路径，其余返回 503；证书就绪后切换 HTTPS，继续提供挑战路径、只把普通 HTTP 请求跳到固定正式域名。
- Nginx 的应用路由在 HTTP 和 HTTPS 间共享，保留原上传/静态路径和限流设置。TLS 接受 1.2/1.3，HSTS 默认 300 秒；只读挂载该域名的 `live/` 和 `archive/`，不挂载 Certbot 账户目录。正式覆盖文件配置同一域名的 Django Host/CSRF Origin 与 Secure Cookie。
- `update.sh` 和 `restore.sh` 共享健康探测：从容器内访问健康路径，必须得到后端 204；HTTPS 检查验证真实 TLS、证书域名和系统信任链，TCP 只连容器环回。私网 HTTP 不跟随跳转；新版健康地址若被旧镜像的 SPA/404 接住，仅此时回退到旧 Django 204 路径。
- Certbot 由运维依环境安装和配置，使用 webroot、续期定时器与证书专用 reload hook。域名、DNS、端口、是否需要备案与部署地点/学校策略有关，不假定已经落实。

## Alternatives considered

由学校网关统一终止 HTTPS 可能更合适，但要先验证可信代理链；不使用这套直连覆盖文件。替换 Caddy 或容器化 Certbot 会扩大范围，现有 Nginx 和宿主机续期可保留原站点行为。

## Verification

本地隔离应用、公开测试及证书签发分开：本次仅检查代码和合成实例；实际公网 DNS、证书签发/续期、TLS 评级和浏览器访问均由运维在获准后验证。步骤见 [README](../../../../README.md)。

## Consequences

启用 HTTPS 后更新、回滚、恢复、备份及续期必须选同一 Compose 组合。更新在停站前检查目标配置文件，拒绝切到不支持 HTTPS 覆盖文件的版本。HSTS 和证书到期会影响可用性；先短期试运行，为续期日志与到期设置告警。
