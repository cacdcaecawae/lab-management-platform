# Agent Note: 本机试用（生产式 Compose + 本机收件箱）与学校邮箱的配置说明

Status: implemented

## Problem

2026-11-17 用户要求：先在本机把平台试用起来；学校邮箱的配置先准备好，账号到了照着填就能用；服务器以后再选。

当时的情况：

- README 只有开发模式（本机跑 Django 和 Vite）和"生产式部署"两段。生产式的 `infra/docker-compose.prod.yml` 从没完整跑过一次（[开发计划](../../../../docs/development-plan.md)里一直标着未验证），而且默认要求 HTTPS cookie、占用 80 端口。
- 邮件设置已经挪进网页（见[系统管理页](../feature/2026-11-17-system-settings.md)），但发送失败时只显示服务器的原文，例如 `535 Error: authentication failed`，不熟的人看不出该改哪一项。SSL 和 STARTTLS 两种加密方式从没在真实连接上试过。
- 不知道学校邮箱托管在哪家，不能写死任何学校的 SMTP 地址。

## Decision

- **本机试用就跑生产式的那一套**（Nginx + Gunicorn + PostgreSQL），叠加一个 `infra/docker-compose.local.yml`：
  - 项目名 `lab-trial`，和开发库的卷分开。
  - 端口只开在 `127.0.0.1`，默认 8090（这台开发机的 8080 被 WSL 占用，80 在 Windows 上也常被占用）。
  - 多一个 Mailpit 容器（固定版本 v1.34.0）作本机收件箱：在"系统管理 → 邮件"里填 `mailpit` / 1025 / 不加密，平台发出的每封邮件都能在 `localhost:8025` 看到。它只是试用用的容器，不在生产 Compose 里，不是应用的依赖。
- **`scripts/trial.ps1`**（Windows PowerShell 5.1 可用，带 BOM 才能正确读中文）：`up`、`admin`、`logs`、`down`、`reset`。第一次运行把 `infra/trial.env.example` 复制成不入库的 `trial.env.local`，密钥和数据库密码换成随机值；`DJANGO_SECURE_COOKIES=0`，CSRF 可信来源带上端口。`up` 等后端就绪后打印地址。
- **不做演示数据**：用户要试的正是真实的开通流程（运维建课题组和账号 → 管理员建学生 → 首次登录改密码）。
- **邮件失败时说明要检查什么**：`core.mail.describe()` 在服务器原文后面接一句建议，测试邮件的提示和"最近一次发送失败"都用它。覆盖：授权码与登录密码、要求先加密、发件人必须等于账号、收件地址被拒、被判垃圾邮件、端口不支持 STARTTLS、服务器在未加密时不提供登录、加密方式和端口不匹配、证书域名或 IP 不匹配、证书不受信任、找不到服务器、连接被拒、超时（云服务器封 25 端口）。
- **账号不是邮箱地址时，没启用邮件也要求填发件人**：测试邮件在启用前就会用已保存的设置发出去。
- **`docs/mail-setup.md`**：去学校网页邮箱哪里开 SMTP、拿授权码，要问网络中心的三件事，各项怎么填，失败提示对照表，本机和服务器上各测一次，授权码的安全注意事项。不写任何具体学校的地址。

## Alternatives considered

- **用开发模式试用**（runserver + Vite）：不用构建镜像。但用户试的就不是将来部署的那一套，Nginx 上传限制、静态文件、cookie、迁移这些问题都要到服务器上才暴露。这次在生产式的栈上走查，确实找到一个只在真实首次使用时出现的问题（运维账号首次登录跳转循环）。
- **生成演示课题组和账号的命令**：切换角色更快。但会跳过真实的开通流程，而这正是用户第一次用时要走的；按 README 的四步手工建也只要几分钟。
- **页面上预置常见学校邮箱的地址**：省得查。但不知道是哪所学校、托管在哪家，猜错的预置比没有更误导；对照表加上"问网络中心的三件事"更可靠。
- **用 Django 的 console 邮件后端代替 Mailpit**：不多一个容器。但邮件只会出现在后端日志里，用户看不到邮件真实的样子，也走不到真正的 SMTP 连接。

## Consequences

- 浏览器验证（2026-11-17，本机试用栈；证据目录 `backend/var/verify-evidence/2026-11-17-trial/` 里只留了一张截图，即 SSL 连明文端口的失败提示，其余结果只记在这里）：
  - `trial.ps1 up` 从零构建并启动，密钥随机，后端就绪；`/admin/` 和它的 CSS 经 Nginx 正常加载。
  - 新建的运维账号首次登录陷入"修改密码 ↔ 系统管理"的跳转循环，页面卡死。外部审查同时报告了这个问题，已修（路由守卫先放行改密页），修复后首次登录先改密、再进系统管理。
  - 邮件：SSL 连明文端口提示"加密方式和端口对不上"；服务器名拼错提示"找不到这个服务器"；本机收件箱发送成功。另起两个带自签名证书的临时 Mailpit（一个 SSL、一个 STARTTLS）：未信任测试 CA 时提示证书不受信任；只在验证时给后端设 `SSL_CERT_FILE` 信任测试 CA 后，SSL 和 STARTTLS 都发送成功，两个收件箱各收到一封；填 IP 时提示"证书上的域名和填写的服务器地址不一致"。走查中发现 IP 不匹配的校验码是 64 而不是 62，已补上。
  - 开通流程：运维建课题组、管理员和导师账号；管理员首次登录时弱密码 `12345678` 被拒（"这个密码太常见了""密码只包含数字"），改密后在"成员"里新建学生；学生首次登录改密。
  - 学生上传 512 MB 文件经 Nginx 入库，用时约 10 秒，SHA256 与本地文件一致；文件在 `labdata` 卷里，Nginx 和 Django 的临时目录随后清空；下载 200、长度正确。
  - 学生提交采购申请后，管理员收到"[采购待初审]"邮件（本机收件箱）。
  - 顺手修了第一期列表页 12 个筛选下拉框没有无障碍名称的问题。
- 测试：邮件建议 15 个用例（每类失败一条），以及"没启用时也要求发件人"。
- 没验证：
  - 学校真实的 SMTP 服务器；HTTPS；宿主机定时任务（本机试用里没有，财务提醒只能手动发）；2 GB 上传（只传了 512 MB）。
  - `trial.ps1 admin`（交互式 `createsuperuser`）和 `trial.ps1 reset` 没经脚本跑过：验证时运维账号是用 `createsuperuser --noinput` 建的，最后用 `docker compose down -v` 清的数据。README 里"用户名、邮箱、密码两遍"是按 Django 的提示顺序写的，没有实际看过。
  - 同一批修复里的"批准后改成空单或 0 元被拒""删除被报销关联的草稿返回 409"只有后端测试，页面上的提示没在浏览器里看过。
- 代价：试用栈的数据和开发库是两套；改端口要改 `trial.env.local` 里两处。
